# ADR 0004：绑定源码的双包候选与分步发布

- 状态：已接受，真实远程发布独立授权与执行
- 依据：[发布操作手册](../../runbooks/release.md)、[发布入口](../../../tools/release/cli.mjs)

## 背景

旧 APK 的签名检查不能证明包含当前源码。双 flavor 是并列产品，同次发布需要一致的源码、签名和资产证据；上传、提升与归档任一部分失败都不能合称完成。

## 决定

构建前记录源码状态，构建后生成不可变候选。候选绑定双 flavor APK、版本、签名证书、插件 manifest、运行资产锁、工具和 L0–L3 报告。正式候选拒绝 dirty、开发标记、未绑定旧产物或缺失门禁；开发检查明确标记不能正式分发。

CLI 默认提供本地 source-record/inspect/prepare/check，不隐式构建、安装、连接网盘或发布。publish/promote/archive 要显式提供 adapter。提升前核对双包齐备并记录旧包快照，只有准确新双包都在“当前最新版”后才归档旧双包；保留幂等状态与部分失败结果。

## 其他选择

不以文件名、mtime 或单包上传成功代表完整发布，不在每次构建后默认清设备数据、上传或移动远端历史文件。

## 后果与验证

候选不能原地修补；源码或制品变化后重新记录、构建与准备。远程 adapter 没有内置真实实现，离线替身测试只证明状态机。当前 APK 检查结果和来源限制见 runbook，不能把历史 APK 的 inspect 通过写成当前源码构建或本轮发布完成。修复发行保留原签名并使用更高 versionCode，低版本回退不默认可覆盖安装。
