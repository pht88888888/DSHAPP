# ADR 0002：显式构建输入、来源锁和分层验证

- 状态：已接受，来源缺口继续保留
- 依据：[资产来源](../native-provenance.md)、[工程规范](../conventions.md)

## 背景

运行资产体积大，部分原生依赖与 staging 配方外置；旧测试隐式读取本机全局引擎会使干净环境失败或形成假绿。持有二进制摘要也不能证明能从上游重建。

## 决定

固定 JDK17、Gradle8.13、Kotlin2.0.21、AGP8.8.2；本机安装路径由显式参数或环境提供。插件、运行资产、原生配方和远程发布基线各有受控来源记录，不借临时绝对路径或全局 DSH 补缺。

L0 只使用锁定工具和小型契约 fixture；L1 显式给官方引擎与 Kotlin 工具；L2 准备 SDK 和大资产，真实构建两 flavor；L3 使用匹配签名候选和受保护用户状态的设备证据。缺输入报告 not-run/失败，不静默跳过。

本仓 native runner 只构建已有配方的三份 linkcompat/sandbox C 源码；外部 Node、引擎、addons 等来源缺口继续如实记录。keyinject 已退休，不列为 active 缺源。

## 其他选择

不以开发机可运行代替可复现输入，也不以合成 fixture 或当前二进制 hash 声称完整上游来源已恢复。

## 后果与验证

基础 CI 可不携带大型资产，但不能宣称覆盖真实引擎或 Android 运行。每层报告实际命令、输入身份、用例数与跳过数；原生编译还需独立验证 ELF、运行行为和历史字节差异。正式发布拒绝缺失层级。当前限制见来源文档与[实施状态](../execution-status.md)。
