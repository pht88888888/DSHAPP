# ADR 0001：按所有权先拆职责，再建立物理模块

- 状态：已接受，实施结果独立记录
- 依据：[批准方案](../reorganization-plan.md)、[所有权清单](../current-architecture.md)

## 背景

引擎、主界面和悬浮球的大类同时拥有状态、资源和决策。直接把成员移到新目录会留下跨模块回调环，行数减少也不能形成独立维护边界。

## 决定

先按进程、安装事务、渲染、窗口、连接和任务的实际 owner 拆职责；管理器保留启动顺序、救援与用户停止等决策。组件通过窄端口获得所需路径、状态和动作，再迁入物理模块。

app 负责 Application/Activity/Service 与跨领域接线。Window/View 和权限 pending 留给当前宿主，通知和 WakeLock 留给 EngineService。日志底座与 app 诊断采集分开。契约不接收万能 AppGraph，不从底层读取 app 的 R/BuildConfig 或实现类。

## 其他选择

仅拆同包文件不能阻止跨层依赖；一次创建全部目标模块又会迫使未拆开的状态跨边界共享。采用分批职责迁移和编译边界收紧。

## 后果与验证

迁移期间物理目录与 Kotlin package 可不同，包名为兼容保留。每批核对资源创建/释放、旧回调世代与用户数据保全，再进行双 flavor 编译与所需行为验证。实际注册和未完成项以[实施状态](../execution-status.md)为准，不由 ADR 宣布全量模块化完成。
