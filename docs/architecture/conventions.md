# 工程组织与协作规范

本规范约束新增与迁移代码；已批准设计见[重组方案](reorganization-plan.md)，实际进度见[实施状态](execution-status.md)。规则生效不等于实现已经完成或门禁已经通过。

## 职责与依赖

以[Gradle 注册](../../settings.gradle.kts)作为物理模块清单，以[当前所有权清单](current-architecture.md)记录运行状态和资源。

- `app` 是装配根，提供运行身份、宿主动作与状态读口。底层模块不得依赖 app、具体 Activity/Service、app 的 R/BuildConfig，不能通过反射或全局服务定位绕过。
- 契约放在所属领域，跨模块确实共用的小型模型才进入 `core/contracts`。接口须能指出提供者、消费者、生命周期和失败语义，不建立万能 AppGraph 或命令总线。
- `core/logging` 写日志和基础事件；需要汇集引擎、窗口、设备、应用版本的诊断在 app 组装，不能让日志底座反向依赖各业务模块。
- Kotlin package 可在物理目录迁移后保留，以维持 Manifest 类名、桥协议和已有引用兼容。library namespace 独立命名，最终 APK 的 15 字符约束只约束运行 applicationId。
- 先按 owner 拆完整职责，再提物理模块。没有独立状态、资源或边界的成员，不为缩短文件而单独搬运。暂留 app 的功能包不等于已成为独立 Gradle 模块。

## 状态与资源

每项可变状态、线程、协程、流、连接、Bitmap、WebView、监听器和系统锁须有唯一 owner。创建处能追到关闭处；完成、取消、超时、异常、宿主 destroy 都有明确结束路径。

| 对象 | 归属与规则 |
|---|---|
| 真实引擎 Process、启动世代、用户停止、救援决定 | 引擎管理器；旧进程回调先核对身份，不结束新进程 |
| 临时 probe/dump 进程 | 探测器；所有出口关闭流、结束子进程和读取线程 |
| 启动参数与环境 | 不可变快照；复制 argv/env/overlay，探测使用真实基线和端口 0 |
| 安装临时目录、版本戳、归档流 | 对应安装事务；完整提交后才写完成判据，失败保留原件 |
| profile 临时改写和隔离备份 | 隔离事务；先备份后写，临时探测结束恢复原字节；失败记录可恢复位置 |
| Window/View、ActivityResult、权限队列 | 当前宿主；完成恰好一次，销毁不误结算新宿主请求 |
| 前台通知和 WakeLock | app 的 EngineService，不随 Activity 重建释放 |
| 页面计时器、观察器、事件和迟到请求 | 插件 apply 实例；dispose 清理，并忽略旧实例结果 |

窄端口应表达能力或事实，例如读取是否忙碌、启动领域桥、提供快照；不能把整个宿主对象作为跨模块可变上下文。业务是否重启、是否降级由现有决策 owner 保留。

## 命名与文件组织

Kotlin 类用 PascalCase，方法和变量用 lowerCamelCase；JS/TS 沿所在组件现有约定。按职责命名 Installer、Writer、Monitor、Session、Transaction 等，名称应对应实际拥有的工作。不要用 `Helper`、`Utils` 或 `Manager2` 掩盖无边界的聚合。

文件头提供准确导航，注释解释约束和失败原因。禁止按“修复 N”堆历史编号；历史过程进入 git/ADR。保持本项目现有错误处理和目录模式，不为结构整理引入依赖、框架或额外抽象。

常量按安装元数据、平台补丁、配置、提示词归属；同一常量只保留一处规范声明。迁移多行字面量时保持源码与运行值字节一致。扫描器、构建器和测试读取同一源码集合，不能假定所有常量都在一个旧文件。

## 错误与数据保全

错误必须保留原始原因和当前结果，不把“写入配置”“Host applied”“HTTP 返回”合称“功能成功”。用户取消、权限拒绝、缺输入、超时、失败和未验证分别表达。

边界层可捕获错误以维持既有降级策略，但不能裸吞异常并返回成功。日志保持脱敏，避免 token、凭据、完整会话或用户文件内容。清理失败不能覆盖主要错误；备份恢复失败应指明备份位置。

用户配置、会话、附件、凭据、工作区及插件状态不得在结构迁移中隐式重建。首次默认值只补缺，registry 版本优先，禁用/卸载不复活。升级与修复优先保留原件；隔离使用可恢复改名，不能用删除冒充恢复。

## 桥与插件契约

桥协议保持方法名、参数、返回、snapshot/invoke 分类、requestId 和异步结果一致。system 与 gecko 适配同一契约；标注 ack 只消费匹配请求，重试不能清掉待确认数据。不同领域信箱继续隔离，原子发布结果后再消费请求。

Android 一个顶层 bundle 内保留 14 个原组件 ID；代码拆模块不增加用户可见的顶层条目。插件安装与更新使用官方事务和 HMR；兼容性、精确版本、旧版恢复和页面同步证据见[插件规范](../agents/plugin-updates.md)。

远程插件生产入口为独立仓库。旧 App 副本仅供溯源，保留尚未归属的 pair-server 和历史测试；不可从旧副本发包，也不能仅凭同版本号覆盖 npm 真实发布基线，见[来源审计](remote-plugin-provenance.md)。

## 测试与静态基线

验收依据实际执行结果和显式输入；默认无资产检查不能隐式读取全局 DSH、机器目录或网络。测试应验证对外行为、资源回收与失败语义，避免仅匹配新文件名、照抄实现或用大量 stub 冒充真实引擎集成。

| 层级 | 输入与证据 |
|---|---|
| L0 | 锁定 Node/工具、小型官方契约 fixture、纯逻辑与协议测试；不依赖 engine.bin 或设备 |
| L1 | 显式提供官方引擎/归档和锁定 Kotlin 工具链；真实解析器、模板、源码锚点与集成行为 |
| L2 | JDK17、Gradle8.13、SDK35、锁定大资产；两 flavor 的实际编译、APK/资产一致性 |
| L3 | 已连接设备、匹配签名 APK、保留用户状态；实际进程、桥、权限与生命周期行为 |

缺输入必须明确失败或 not-run，不隐式下载替代品，不用零用例或跳过当成功。合成 fixture 只证明其覆盖的契约，不声称线上或原生运行已验收。测试报告写用例数、跳过数、输入身份与证据，命令退出 0 不是唯一依据。

体积策略覆盖生产模块的手写 Kotlin，排除 build、.gradle、tests 与 fixtures。未列历史基线的新增 `.kt` 不超过 1000 行；历史超过 1000 行的文件按迁移后的真实行数逐项锁定 owner、原因与上限，只许收缩。基线缺项、锁定文件缺失和编号式注释均应失败，不能靠隐藏文件或抬高上限通过。入口为[源码策略检查](../../tools/check-source-policy.mjs)，其[行为测试](../../tools/test-source-policy.mjs)验证检查器的接受与拒绝契约。具体基线以最终受控配置为准；fixture 测试通过不代表仓库当前基线或整体验收已通过，本规范不猜测仍在迁移的文件行数。

架构入口为 `bash tools/check-architecture.sh`。物理模块检查由 [check-module-boundaries](../../tools/check-module-boundaries.mjs)读取实际 Gradle 注册、源码声明、直接依赖和许可方向，旧 Kotlin package 不改变真实 module 所属。[分层门禁与命令](../runbooks/testing.md)是 L0–L3 操作入口，不将某层通过等同整体通过。不能为过门禁删断言或换成只读薄入口；边界检查覆盖实际源码闭包。基线调整需说明真实职责变化、当前数值和替代约束，由独立审阅确认。

## 构建、资产和发布

同一构建使用固定工具链和显式输入。插件统一构建并逐文件校验；运行资产与原生来源分别进入锁。仓库维护源码的本地编译与外部来源恢复是不同结果，构建 ELF 成功也不证明 Android 行为或历史字节复现，见[原生来源](native-provenance.md)。

发布绑定构建前源码记录、双 flavor APK、签名、运行资产、插件 manifest、工具版本和分层报告。开发候选与正式候选区分，历史 APK 不自动绑定当前源码。远程动作使用显式 adapter，并核验部分失败和幂等重试，见[发布手册](../runbooks/release.md)。

影响依赖方向、状态所有权、构建输入、桥协议或发布身份的决定须新增 [ADR](adr/README.md)。批准的设计原文保留；后续偏差写新决策和实施状态，不覆盖历史审批记录。
