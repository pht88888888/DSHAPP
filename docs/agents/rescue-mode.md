# 引擎或页面启动失败：手动处理

本文取代旧的救援模式设计。客户端不再自动进入安全模式、隔离插件、重载页面或重启引擎。

## 现行行为

- 正常安装、解包、Node 校验和 profile 状态照常执行；不会删除 `$DSH_HOME`、会话、凭据、工作区或插件 registry。
- 引擎启动失败或意外退出后保留事实错误、日志、诊断导出和备份入口；失败进程会释放，避免下一次重试误复用未就绪实例。
- WebView/Gecko 渲染进程退出会同步销毁失效宿主并显示原生失败状态。只有用户点击 Retry/Reload 才创建新宿主或重新加载。
- 用户可手动重试引擎、重载页面、查看日志并导出诊断；这些动作不静默修改插件或用户资料。

## 不再存在的路径

旧版的 `RescueBoot`、`RescueAutoRetry`、启动前 `--dump-config` 体检缓存、插件隔离事务、救援 prompt/命令信箱、WebClientWatchdog 和自动恢复控制器均已移除。历史文档仅作故障记录，不是当前实现或验收要求。

## 诊断与升级

遇到持续失败时，先导出诊断和用户备份，再记录引擎/页面错误及手动操作结果。升级不得清空数据、复活用户禁用的插件或覆盖既有备份。旧救援文件不再由客户端读写，升级时不清理它们；旧版已移动的文件也不会被自动复原。

更换机制的候选设计见[事务式启动与升级提案](../architecture/transactional-startup-proposal.md)，未实现。
