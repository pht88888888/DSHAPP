## 1. 目标

在 Android 本地运行 DSH，保留完整的编程 Agent 工作方式，同时降低整包更新频率，避免升级或救援破坏用户环境。

核心原则：

1. 保留真实命令执行、文件操作、PTY、插件、子代理、后台任务、会话持久化和权限审批，不退化为聊天客户端。
2. 安卓基座、DSH 内核、插件和用户数据分层管理。
3. 故障时优先切换修复环境，不先清空日常环境。
4. 程序更新可校验、可切换；回滚与修复撤销以已声明的一致性边界和恢复条件为前提，不以回滚代码代替恢复数据，不承诺撤销外部或不可逆副作用。
5. 基础 Agent 不依赖 Shizuku 或 Root，但支持二者作为可选增强。

“不打折扣”不代表所有桌面二进制天然兼容，也不代表突破 Android 系统权限和后台限制。模型推理是否在本地取决于模型服务配置，本方案主要讨论本地 Agent 编排与工具执行。

## 2. 组件职责

| 组件 | 职责 |
| --- | --- |
| Android | 提供应用权限、进程、文件访问和执行边界。 |
| Termux 工具环境 | 提供适配 Android 的命令工具、包和依赖库；不只是终端窗口，也不是完整 Linux 虚拟机。 |
| Node.js | 执行 JavaScript，提供文件、网络、子进程等运行接口。 |
| npm / pnpm | 将软件包及依赖安装到磁盘；安装成功不等于运行兼容。 |
| DSH 内核 | 本文对 DSH 启动器、执行框架和配套依赖的简称，不是操作系统内核。 |
| profile | 组织插件依赖、启用组合和用户 patch，不是虚拟机或安全沙箱。 |
| 安卓基座 | 托管运行时与实例，承载 DSH 页面，连接 Android 系统，并管理更新原语及救援切换；不另建业务界面。 |

基座不重新实现 Agent 循环、模型编排、会话和认证语义，复用官方 DSH；必要 Android 平台判断及兼容依赖按第 4.8 节最小补丁流程处理。

## 3. 总体架构：双内核、三环境

```text
一个安卓应用
├─ 安卓基座：DSH 页面容器、运行监督、系统能力接口与救援调度
├─ Android 工具底座：Termux 工具、Node、原生兼容库
├─ 一号 DSH 内核：日常版本
│  ├─ A 日常环境：独立 HOME + 日常 profile
│  └─ R 修复环境：独立 HOME + 修复 profile
├─ 二号 DSH 内核：已验证应急版本
│  └─ E 应急环境：独立 HOME + 应急 profile
└─ 可选权限代理：Shizuku / Root
```

### 3.1 隔离与共享

- 一号、二号各有独立的 DSH 依赖树，不能只复制启动文件却共享可变依赖。
- A、R、E 分别使用独立 DSH_HOME，隔离 home patch、模型设置、凭据、插件和其他可变状态。
- R 与 A 共用一号内核代码，不共用可变插件安装区。
- 二号保持精简和已知可用，不随一号自动同步升级。
- 正常仅运行日常实例，修复按需启动；切换前停止并确认原进程退出。
- Node 和原生工具底座仅可在兼容验证通过后共享，首版即按版本引用受管运行时；正常包管理不得原地修改已激活或救援引用的版本。版本目录封存是管理约束，不是同 UID 下的安全隔离。
- 用户工具链使用独立安装前缀与版本记录，不覆盖受管 Node、必要原生库和救援工具。缓存可以共享，但包激活、PATH 和动态库解析不得隐式串用；无法使用独立前缀的工具应先完成隔离或受管部署适配，不能直接修改共享底座。
- E 使用固定运行时、最小工具集及明确的 PATH、库路径，不继承 A 的环境变量或启动脚本。R 同样不依赖 A 的用户工具链。
- 二号应急能力按完整救援组合验证：K2、E 的 profile 执行依赖与配置版本、匹配运行时及原生库、必要桥协议与界面适配、最小修复工具。不得把账号秘密固化进发布载荷；模型不可用时仍须支持本地最小恢复。
- 基座升级必须保留或交付至少一个已验证可用的救援组合；旧组合不兼容时，不能先破坏它再依赖联网补齐新组合。
- 共享底座故障可能影响两套内核，因此仍需要不依赖 Node 的原生恢复页。
- 独立目录不等于安全隔离：同一 Android 应用身份下的代码可能访问其他环境文件，必须另行约束修复权限。

## 4. 安卓基座能力契约

| 能力 | 要求与验收重点 |
| --- | --- |
| 命令执行 | 支持真实子进程、管道、标准输入输出、退出码、信号、取消和子进程清理。 |
| PTY | 支持交互式程序、终端输入和尺寸调整，不能用一次性命令代替。 |
| 工作区文件 | 验证搜索、读写、文件锁、链接、权限与原子替换等语义。 |
| 工具链 | Node 和包管理器可用，预留 Python、编译工具和其他工具链适配路径。 |
| 网络与 MCP | 支持模型流式连接、代理、证书、HTTP/WebSocket，以及可适配的 stdio 工具连接。 |
| 多任务 | 保留子代理、后台任务与取消机制，不以禁用文件锁绕过多进程互斥。 |
| 权限 | 保留审批、拒绝反馈和权限模式；真实报告合作式限制，不把 LD_PRELOAD 等用户态拦截报告为完整内核沙箱；不能正确表达时先适配或阻断。 |
| 生命周期 | 使用前台服务、必要 WakeLock、电池优化引导和状态记录，准确报告系统终止。 |
| 原生桥 | 端口、目录、凭据、文件信箱及停止进程逻辑按实例归属管理。 |
| 恢复控制面 | 两套 DSH 都不可用时仍能查看诊断、导出日志和执行受控恢复。 |

### 4.1 工作区

主执行工作区优先使用支持正常文件语义的应用私有存储。公共存储及文件选择器目录可用于导入、导出和同步，不能默认当作普通 Unix 工作区。直接在外部目录执行任务前，须验证链接、执行权限、文件锁和原子写等语义。

### 4.2 Shizuku 与 Root

- 普通应用通道为默认必需通道，承担基础 Agent 能力。
- Shizuku 与 Root 均为可选增强；ADB 启动的 Shizuku 通常是 shell 权限，不等同 Root，能力按实际检测。
- 不让整个 DSH 或所有插件以 Root 身份运行。
- 高权限操作通过独立代理执行，明确标识实际通道并进行必要审批。
- 普通命令失败不能静默提权重试。
- 服务停止、授权撤销和设备重启后重新检测；增强通道失效不影响基本使用。
- 修复环境不默认获得更高权限。

### 4.3 精简基座与插件的职责边界

基座不设置独立业务操作界面，但必须承担 DSH 页面展示。用户日常看到的是官方 DSH Web GUI 及插件提供的页面，而不是另一套原生控制台。启动 DSH 后，所有面向用户的基座日常设置通过官方插件设置中的“安卓基座”入口提供，包括第 5.3 节的备份与导入导出；不另建原生备份页或设置中心。故障时最小原生恢复出口和 Android 系统授权选择器不属于日常设置界面。

基座的固定职责为：运行托管、页面承载、系统桥接与救援调度。它既提供接口，也保留不依赖 DSH 插件的确定性监督逻辑，避免插件失效后失去恢复入口。

| 基座负责的机制 | 插件负责的功能 |
| --- | --- |
| 运行时准备、进程启动停止、就绪与退出诊断 | 任务管理、状态展示和诊断解释。 |
| Android 信息获取与受控行为接口 | 设备管理、自动化流程及业务编排。 |
| 系统授权及 Shizuku / Root 权限代理 | 权限设置页面、能力使用引导。 |
| 更新包验签、兼容校验、暂存部署、切换与回滚原语 | 更新页面、版本选择和更新提示。 |
| A → R → E 的有限状态调度 | 模型诊断、修复建议和经批准的具体修复流程。 |
| 日志采集、快照、备份与恢复原语 | 日志浏览、报告和备份管理页面。 |
| 通知发布、必要前台服务通知、系统悬浮窗口与媒体/交互执行 | 业务通知内容、悬浮窗外观、宠物素材、声明式行为与业务编排。 |

实现上划分为运行监督器、系统能力适配器、协议与权限网关、极薄应用容器四部分。内核包管理属于受控管理机制，不扩展为另一套业务系统。

监督元数据校验与最小原生恢复入口先初始化，再挂载 DSH 页面、悬浮媒体、传感器和自动化等可选模块。提供不加载扩展的启动路径及有界启动失败标记；可选模块持续失败时可由原生入口停用，不在每次启动时无条件重载故障资源。按崩溃传播与资源风险选择可丢弃组件或独立进程，不要求所有模块多进程化；隔离方案须真机验证，不能把异常捕获等同于隔离原生崩溃。

### 4.4 DSH 页面容器

- Termux 工具环境嵌入本应用，不要求用户另外安装或打开 Termux App。
- 基座直接启动工具环境中的 Node 和 DSH，不依赖模拟用户在终端输入命令。
- 基座优先用系统 WebView 验证并承载官方页面，以减少安装体积和常驻内存；它是工程首选而非已验证结论。只有证实官方登录或必需功能无法满足时才评估 GeckoView，首版不默认同时内置两套 Web 内核。
- 获取当前实例的本地服务地址及认证信息，通过 HTTP/WebSocket 对接 DSH；不能因为服务监听 127.0.0.1 就省略认证。
- 基座处理键盘、返回键、窗口与页面生命周期、文件选择及必要系统授权交互；业务界面与内容由 DSH 和插件提供。
- 切换 A、R、E 时，待目标实例满足就绪条件，再将页面连接到目标实例；同步更新认证与桥接上下文，避免旧页面继续控制旧实例或误用新实例权限。
- 页面是否可见、是否加载成功与引擎是否健康分别记录，不能把白屏直接等同于内核故障。
- 页面桥可处理键盘、主题和界面交互，但不能作为 Agent 访问原生能力的唯一通道。
- 全部 DSH 环境无法启动时，只显示最小原生恢复出口，例如重试、日志导出和受控恢复包导入，不建设独立业务设置中心。

### 4.5 系统能力接口与封装

功能调用链：功能插件 → Android 桥接客户端 → 版本化协议 → 基座能力网关 → Android API 或已授权权限通道。

DSH 侧使用精简桥接插件统一封装传输，其他功能插件不自行实现信箱协议，也不直接依赖 Kotlin 内部类。协议可扩展、能力可发现，不意味着预先申请所有 Android 权限。

接口能力域包括：

1. 能力发现：协议版本、方法、限制、权限状态和不可用原因。
2. 设备信息：系统、架构、内存、存储、电量、网络；敏感信息另行授权。
3. 运行控制：查询实例、诊断、启动停止及请求切换修复环境；具体执行由监督器裁决。
4. 存储交互：授权目录、文档访问、导入与导出，不替代 Node 的普通工作区文件操作。
5. 系统行为：通知、打开链接、剪贴板等明确操作。
6. 设备自动化：按实际授权提供截屏、无障碍等能力，并声明前台及交互要求。
7. 权限代理：Shizuku / Root 状态、授权流程和受控高权限任务。
8. 更新与恢复：校验、部署、切换、快照及经授权的恢复操作。

接口需有操作白名单、参数校验、稳定错误码、实际权限通道、超时及取消语义，不公开无限制反射调用或默认任意 Root 执行口。某些能力需要新增原生实现、manifest 声明或 APK 更新，不能承诺仅安装 JavaScript 插件即可增加任意系统能力。

### 4.6 桥接传输与可靠性

参考 DSHAPP 的私有文件命令信箱，作为低频控制操作的初版候选；并非全部通信必须采用文件。传输实现封装在桥接客户端之后，允许后续替换。

- 请求包含协议版本、实例身份、启动轮次、请求 ID、方法、参数和截止时间。
- 响应包含结果或错误，以及实际执行通道；事件支持订阅、取消订阅与长任务进度。
- A、R、E 按目录和启动轮次分区，拒绝过期实例遗留命令。
- 使用并发队列或每请求独立文件，不能仅靠自增 ID 解决单文件覆盖。
- 使用临时文件与原子发布，记录处理状态并控制重复执行；先返回结果再清理已消费请求。
- 超时不等于未执行，不自动对有副作用的操作盲目重试。
- PTY 字节流、视频和大文件使用适合的独立通道，不强塞进 JSON 控制信箱。
- 同应用身份的插件不能仅凭自报名称获得高权限；信箱目录或令牌本身不是针对同 UID 任意代码的强隔离。高权限仍由可信基座按授权与审批裁决。

### 4.7 救援与能力验收补充

基座调度不依赖模型：收集诊断 → 停止并确认原实例退出 → 按规则启动 R 或 E → 更新页面连接。阈值与重试上限通过原型确定。

修复插件组织诊断与修改计划，基座验证目标停止、快照完成和权限条件。基座不代替模型分析业务故障，也不能将全部故障判断交给可能无法启动的插件。

新增验收：DSH 页面在 A/R/E 切换后连接正确；旧实例请求不越过启动轮次；并发命令不覆盖；重复请求不产生未受控重复副作用；无插件时必要授权、前台通知与最小原生恢复仍可工作。

### 4.8 官方内核与 Android 兼容层的边界

- 以可校验的官方发行物为上游基线，通过官方启动入口承载 Web GUI；不另写聊天前端，不改变 Agent 循环、会话数据语义、官方账号协议和插件标准。
- 用户已选择允许最小 Android 兼容补丁。优先次序为外部运行资产/标准扩展点 → 平台适配层 → 必要的平台判断或绑定加载补丁；不得把该例外扩大成业务分叉。
- 每个补丁记录上游提交/包版本、原始哈希、目标文件、原因、补丁内容与哈希、应用后哈希、测试、许可证及移除条件；仅在匹配 preimage 上应用，升级不匹配即失败，不模糊套补丁。
- Android 发行物标为“官方基线 + Android 兼容补丁”，不能宣传官方包完全未修改。补丁集与构建脚本可追溯，保留原版载荷和上游反馈入口。
- Node 原生绑定、PTY、文件锁、链接、沙箱后端及工具逐项验证。允许修正平台判断，不允许禁用互斥、吞错误、假造权限或改变认证校验换取启动。
- 首发 ARM64、侧载，暂以 targetSdk 28 沿参考私有目录二进制执行路线验证。该路线及等长 ELF 前缀替换对包名/路径有实际约束，须在确定 applicationId 前核对；不是所有 Android 方案的永久限制。
- 提升 targetSdk、商店发行或不同 ABI 是另一个兼容性项目，必须重新验证可执行文件部署、权限与前台服务；不能只改一个 manifest 数值。
- 发行前核对 Termux/Node/原生库及参考代码的许可证、二进制来源、对应源码/声明等分发义务，不因开源而假定可无条件搬用。
- 关键能力若需改变上述禁止语义才能实现，暂停对应路线并重新决策，不以首发全功能要求授权任意改官方。

### 4.9 横竖屏、分屏与界面适配

采用“原生窗口处理 + 单一布局适配器 + 局部界面增强”的三层结构，不通过旋转重启 DSH 或重新创建会话。

| 层 | 职责 |
| --- | --- |
| Android WebContainer | 处理实际应用窗口、系统栏/刘海 Insets、IME Insets、返回键和页面生命周期；避免旋转时无谓销毁 Web 页面。 |
| 基座配套 LayoutAdapter | 唯一决定实际布局，发布布局标志，进入/退出时执行可撤销的前端适配；不是另一套原生业务界面。 |
| 局部界面插件 | 消费实际布局标志，调整输入区、顶栏和设置页，不自行决定横竖屏，不改变皮肤或会话身份。 |

参考 `yunhesi-wind/DSH-plugins` 的 `AndriodTablet` 分支，布局设置包括 `layoutMode: auto | mobile | official` 与 `lastLayout: mobile | official`。设置所有者与布局执行者分开；只保存偏好的插件不重复注册客户端适配器。

自动模式使用应用窗口宽高比 r，而不是物理屏幕方向或鼠标类型：

| 条件 | 实际布局 |
| --- | --- |
| 手动 mobile / official | 锁定指定布局，不随窗口变化切换。 |
| auto 且 r > 4/3 | official，沿用官方响应式布局。 |
| auto 且 r < 3/4 | mobile，启用手机适配。 |
| auto 且 3/4 ≤ r ≤ 4/3 | 保留上次实际布局；初次无历史时为 mobile。 |
| 窗口尺寸为零或无效 | 保留当前实际布局，不写入异常状态。 |

此滞回策略用于平板分屏、浮窗及接近正方形的窗口，避免边界来回跳动。快速旋转时，历史异步写回不得反向覆盖最新实际布局；写失败应有界重试，卸载后停止回调和排队写入。

键盘适配与布局决策分开：`visualViewport` 可用于输入区可见高度、滚动与遮挡修正，但不驱动自动布局模式；原生侧还应区分仅由 IME 引起的窗口高度变化，防止某些 WebView 的 resize 行为造成误切换。具体稳定窗口尺寸来源须在原型验证。

适配器发布唯一实际布局标志，现有参考使用 `data-dsh-android-layout` 和 `data-mobile`；局部增强只跟随，不写入或重新推导这两个标志。退出 mobile 或卸载插件时，移除其样式、属性、监听器和观察器；借用的 DOM 控件在仍由本插件持有且原父节点有效时归还，不复活已被原所有者移除的控件。

现有输入区/顶栏增强部分依赖编译后的类名，因此必须绑定兼容的 DSH 前端版本并检查 DOM 结构。结构不匹配则关闭对应增强、保留官方可用界面并记录诊断，不强行套用 CSS。优先使用稳定 Slot/语义属性，但不能假定未验证的官方扩展点存在。

基座配套适配器与普通 profile 插件分别交付：同名适配器只允许一个所有者。参考分支的 `native-adapters` 是匹配 APK 的 late overlay 部署归档，不能直接加入 profile bundles 重复安装；移植前核对宿主版本、资源戳、preimage 和文件哈希。适配资源改变后同步重建对应资产与版本戳，仅提交源代码不等于已完成 APK 发布。

### 4.10 官方 DSH 账号登录与认证

#### 4.10.1 必需能力与范围

官方 DSH 账号登录是首发必需能力和发行阻断验收项，不是可选插件功能。Android 版必须能够通过目标官方版本支持的流程完成登录、恢复登录态、重新认证和退出，并实际使用该账号提供的已授权能力。不能以“支持手填 API Key”“能显示登录按钮”或“能打开网页”替代登录成功。

区分三类状态，不混用凭据：

1. 官方 DSH/DeepSeek 账号登录及其模型服务授权。
2. 官方 Web GUI 连接本地 DSH 服务的认证与连接会话。
3. 第三方模型、MCP 或其他插件自己的认证。

保留官方账号与登录语义，不重写认证服务、不代收密码、不绕过验证码或服务端校验。第三方认证可复用通用授权承载能力，但不承诺所有供应商都能使用同一种流程。

#### 4.10.2 官方流程复用与原生承载

由官方 DSH 的账号组件发起并确认登录；Android 基座负责系统浏览器/受控授权窗口、页面导航、应用回前台、必要回调路由及生命周期。日常主界面仍为官方 Web GUI，不另建一套账号系统。

实施前必须锁定目标 DSH 提交，核查账号组件、登录服务、Web 与 Desktop 差异，以及其实际跳转、轮询/回调和凭据存储路径。不能假设 Desktop 的登录窗口桥在 `dsh web` 模式下天然可用。若官方 Web 缺少承载能力，先使用官方扩展点和基座桥，再评估第 4.8 节允许的最小平台补丁；不得改变服务端认证与安全校验，仍无法完成则登记发行阻断项，不能削弱登录要求。

外部授权优先使用服务端支持的系统浏览器/Custom Tabs 等方式；若目标官方流程要求受控内嵌页面，需核对 Cookie、弹窗、重定向和 WebView 限制后验证。前轮源码评审已在第 7 节所列官方提交识别出 Web 发起、Host localhost 回调、state 与 PKCE 的现有链路，应优先复验并承载该链路；不擅自替换为设备码或自定义 scheme。该源码事实不等于 Android 登录通过，最终选型服从锁定版本与真机结果。

如流程使用回调：按官方协议校验 state/nonce/PKCE 等适用字段，绑定发起环境、启动轮次和单次授权事务，限制回调来源与目标；仅在官方协议支持时使用对应 App Link、自定义 scheme 或 loopback。旧环境、过期、重复和未发起的回调不得使新环境登录。若采用官方轮询流程，则保留取消、到期和结果确认，不强行改成回调。

登录完成由官方账号服务结果和后续受认证操作共同确认，不靠页面标题、URL 或客户端缓存布尔值判断。取消、断网、验证码/多因素交互、超时与服务端拒绝应明确反馈并允许重试，不触发内核切换或破坏已有会话。

#### 4.10.3 登录态与凭据边界

- 登录态在重启、旋转、覆盖升级及兼容内核升级后按官方语义恢复；过期、撤销或不可继续使用时明确重新认证。前轮锁定版本未发现主动 token 刷新流程，不新增“自动刷新”承诺，不通过清空全部数据解决。
- A/R/E 账号凭据分别归属于独立 DSH_HOME；R/E 的模型配置及授权不能依赖 A 插件或临时登录窗口。默认不共享整个 Cookie jar、token 文件或可写账号存储。
- 若允许把账号授权用于另一环境，必须通过用户明确授权且符合官方支持的方式导入或重新认证；不直接复制正在写入的凭据目录。修复操作不擅自退出、删除或覆盖 A 的账号。
- 浏览器 Cookie/Web 存储、本地 GUI 认证和账号持久凭据分别管理；端口、origin、容器或浏览器内核变化时验证重新连接与登录态恢复，不默认 Cookie 可直接迁移。
- 不把账号 token、验证码、授权码、Cookie、认证 URL 中的敏感参数或完整回调写入日志、诊断包、工具结果、聊天内容或悬浮窗事件。插件查询只返回必要的脱敏账号状态，不提供读取原始凭据的通用接口。
- 凭据遵循官方存储契约，原生侧新增秘密使用 Android Keystore 等适当保护；不能在未适配官方读取方式前直接改写或加密其文件。应用私有目录与 Keystore 不构成针对同 UID 任意插件的完整隔离。
- 退出账号调用官方退出逻辑，清除对应环境应清理的会话与凭据；是否同时撤销服务端会话服从官方能力。不得误删用户会话记录、工作区或其他环境账号；提供正常的换号与重新登录入口。

#### 4.10.4 基座授权承载接口

在统一 SDK 中预留授权会话能力：查询承载方式、打开官方批准的授权目标、回收/取消授权窗口、接收受校验的结果及查询事务状态。状态机至少覆盖发起、等待用户、等待服务端、完成、取消、失败与到期。

接口限制目标来源、回调路由和暴露数据，事件只携带脱敏状态；不得扩展为任意网页提取 Cookie、读取密码或截取其他应用授权码的工具。官方账号语义仍由 DSH 管理，基座只负责承载与可靠路由。

### 4.11 系统悬浮窗与插件扩展

#### 4.11.1 定位与范围

保留 DSHAPP 系统悬浮窗的交互能力，作为安卓基座机制，而不是 DSH 页面内部浮层。基座负责窗口、媒体、交互和行为执行；DSH 插件提供素材、声明式策略、设置与业务编排。

`dsh-app-pet@1.0.3` 仅用于确认功能需求，不作为兼容目标。不兼容其旧信箱、字段、工具或安装路径，不建设迁移/兼容层，不承诺原插件直接可用；本项目以自己的版本化协议与 SDK 为准。宠物形象、24 段素材、固定动作名和业务文案均不写死进 APK。

#### 4.11.2 分层与基础入口

```text
DSH 扩展插件：素材、动作池、状态映射、文案与业务操作
                  ↓ 统一 SDK / 版本化协议
基座：所有权仲裁、配置校验、行为调度与资源管理
                  ↓
原生窗口 / 触摸与焦点 / 拖拽与运动 / 系统授权
                  ↓
可替换内容渲染器：静态图、帧动画、透明视频
```

- 系统悬浮窗授权、创建/销毁、显示隐藏、拖动缩放、贴边折叠、展开面板、焦点及返回行为由基座控制。
- 保留不依赖 DSH 插件的最小悬浮入口，可显示连接/故障状态并打开主页面或恢复入口；用户可关闭，权限不可用时使用应用内入口及可用的系统通知兜底，不保证悬浮窗始终存活。
- 宠物模式等属于插件扩展。插件失效、DSH 断连或进入修复环境时，撤销其运行控制并回到基础入口；故障恢复本身不依赖宠物或模型。
- 视觉区域与触摸区域分开定义；透明不等于点击穿透。默认不抢焦点，展开需输入的面板时才按明确交互规则切换，防止遮挡其他应用或吞掉系统操作。
- 旋转、分屏、系统栏及 IME 改变时重算可用边界，约束位置并保留可找回入口；几何接口明确 dp/px、坐标空间与密度转换。

#### 4.11.3 功能契约

以下为本项目接口草案的能力分组，不是现有 DSH API；方法签名、配额和错误码在协议设计时确定。

| 能力 | 预留操作与行为 |
| --- | --- |
| 窗口与权限 | 查询支持能力与授权状态、申请系统授权、创建/更新/显示/隐藏/销毁；支持前后台策略、尺寸、位置、贴边、面板及焦点模式。 |
| 素材与播放器 | 导入、检查、引用和释放素材；静态图、帧动画、透明视频能力发现；播放/停止及加载、播完、失败事件。 |
| 声明式行为 | 整份校验与应用、读取、重置；动作池、随机权重、动作链、转向翻转、点击/拖动回应、自动移动和运行状态映射。 |
| 交互与运动 | 点击、长按、拖动结束、抛掷、碰撞、菜单选择事件；配置移动距离、周期和物理参数，受基座边界与资源限制。 |
| 状态与消息 | 发布/清除状态，展示/关闭提示，配置有效期；点击能打开归属明确的环境、会话或任务。 |
| 配置与所有权 | 获取/释放扩展控制租约、读取实际配置与 revision、导出/恢复配置、撤销或清理扩展。 |

运动积分、动画循环和已声明的动作调度在基座内执行，不通过 Node 或文件信箱逐帧驱动。插件只提交策略和低频控制；输入事件回传应节流，不把每个触摸采样都变成跨进程请求。

#### 4.11.4 素材与渲染约束

- 插件素材先经基座检查并导入受管资源区，使用资源句柄引用，不允许播放器按任意外部路径读取文件。控制消息与大素材传输分离。
- 真实文件内容哈希用于校验和去重，不用字节数代替内容指纹；限制类型、单文件/总量、解码尺寸、并发播放器和资源占用。
- 透明视频能力按实际渲染后端及设备验证，不能只凭扩展名或 MIME 承诺 alpha 支持。不可用时退回帧动画、静态图或基础悬浮球，并报告原因。
- 可参考 DSHAPP 的透明 WebView 内 video → canvas 内容渲染和双缓冲切换，但窗口、触摸与物理由原生掌握；该媒体后端与主 GUI 的浏览器内核选择分别验证。
- 媒体 WebView 只加载基座受控播放器及批准素材，不执行插件提交的任意网页或脚本；不得把 Android 高权限桥暴露给不可信内容。
- 播放器按需创建；隐藏、锁屏、后台策略或节能条件触发暂停绘制/解码，必要时释放。内存压力、解码失败、资源丢失能局部降级，不拖垮主 GUI 或引擎。

#### 4.11.5 生命周期、持久化与仲裁

悬浮服务属于基座，A/R/E 不各自复制一个系统入口。配置按环境与扩展归属持久保存；资源可按内容哈希去重，但引用、权限及清理必须保留所有权信息。

当前激活环境持有有效控制租约；同一窗口多插件竞争由基座仲裁，不采用无规则的最后写入覆盖。用户手动设置优先级和重置语义明确，插件重启不能无条件覆盖用户后续修改。

切换环境时撤销旧租约、事件订阅和排队控制，清除旧任务状态；可以保留已缓存外观，但不得继续显示旧任务正在运行。插件停止/卸载时立即撤销运行控制；已保存外观仅按用户明确的保留策略继续使用，否则回退基础入口。资源引用解除后按保留与回收策略清理。

基座以实际配置 revision、资源完整性和安装标识确认状态，插件本地“曾应用成功”标记不能替代查询。备份、恢复和重装后均须重新核对，配置持久化不代表具备永久权限或窗口必然可见。

#### 4.11.6 DSH 状态桥接

由 DSH 侧桥接插件读取目标版本实际支持的事件，转换为统一事件，不解析聊天 DOM 猜测状态，不要求修改官方内核。参考状态集合为 `idle / thinking / working / waiting / error / result / success`；连接中断、状态未知和恢复状态另行表达，不能伪装成 idle 或 success。

状态携带环境 ID、启动轮次、会话/任务 ID、序号和有效期。支持跟随指定会话或聚合模式；聚合优先级显式定义。拒绝旧轮次、过期及乱序事件，避免后台任务的迟到完成通知覆盖当前任务。点击打开会话时校验目标归属；敏感内容及状态文案在锁屏等场景按隐私策略隐藏。

### 4.12 面向插件的完整能力平台

首发实现本节及第 4.14 节明确列出的稳定能力域、可调用功能与验收，不仅建立空接口；不要求穷举全部 Android API。统一 SDK 封装传输、错误、取消、订阅及资源句柄；插件不各自实现信箱，不直接依赖 Kotlin 内部类。硬件不支持时返回真实原因不是删除实现；发行支持矩阵内必须有正向功能证据。

| 能力域 | 插件使用方向 |
| --- | --- |
| capabilities / permissions | 协议与功能发现、限制和不可用原因、系统授权与审批。 |
| device / lifecycle / window | 设备、电量、网络、前后台、锁屏、窗口及 IME 状态。 |
| overlay / media / interaction | 悬浮球、宠物、任务提示、快捷操作与受控面板。 |
| storage / documents / share | 系统文件/目录选择、导入导出、分享及访问授权。 |
| notifications / intents / clipboard | 通知、返回会话、打开应用/链接及受限制的剪贴板交互。 |
| runtime / diagnostics / recovery | 实例查询、日志、诊断包、R/E 切换、快照与恢复。 |
| updates / packages | 版本查询、验签、兼容校验、暂存部署及回滚。 |
| automation / privilege | 按授权提供截屏、无障碍与 Shizuku/Root 增强。 |
| extension storage / assets / events | 扩展配置、资源登记、版本迁移、事件订阅及清理。 |
| camera / microphone / audiovisual | 拍照、预览、录像、录音、播放与实时流，显式启动/停止和背压。 |
| location / bluetooth / sensors | 单次/持续位置，蓝牙发现与连接、BLE 服务和特征读写/订阅，受限传感器采样。 |

统一契约要求：

1. 每个能力声明协议版本、支持情况、输入输出约束、权限、实际通道、配额及交互要求；未实现返回明确的 `NOT_SUPPORTED`，不得伪装成功。
2. 接收请求、配置提交、资源就绪、实际窗口可见分开报告；超时支持按请求 ID 查询最终结果，有副作用操作具备幂等/去重语义。
3. 请求与事件绑定环境、启动轮次及可信网关确定的授权上下文；插件自报名称不是权限凭据，同 UID 限制仍适用。
4. 订阅可取消，资源有所有者、有效期及释放规则；断连、切换和卸载后清理，控制事件洪泛、排队长度和资源耗尽。
5. Android 系统授权、DSH 操作审批与高权限通道授权分别处理；能力发现不意味着预先申请全部权限。
6. 高权限、恢复及更新操作保留基座裁决和审计，不暴露任意反射、任意原生代码或默认 Root 执行入口。
7. 新能力若依赖 manifest 或新增原生实现，仍需升级 APK；协议扩展不能承诺 JS 插件获得系统尚未提供的能力。

首轮以宠物功能需求验证悬浮能力，再用任务通知、文件导出和诊断恢复验证接口的通用性；不以复刻某个 pet 包作为验收标准。

### 4.13 官方插件标准优先与社区部署

#### 4.13.1 核心准则

以目标发行版本的 DSH 官方插件开发文档、包声明、Loader、Host/Client 生命周期及实际 API 契约为核心准则。本文的 Android SDK 是可选能力扩展，不是新的插件标准；不得要求所有社区插件改写为安卓专用格式，或以自定义插件市场契约取代官方插件管理。

不依赖 Android 能力的社区插件应沿用官方安装、启停、配置和卸载方式，不强制依赖 Android SDK。需要设备能力的插件通过标准 DSH bundle 接入桥接服务，按能力发现结果启用对应功能。SDK、服务及方法命名在实现前通过官方检查接口及目标版本文档核对，本文能力域不视为已经存在的官方 Service。

#### 4.13.2 保留官方契约

- 包与 Loader：沿用 `package.json` 的 `dsh.bundle.patch`、包导出及官方 patch 组合机制；保护 profile 依赖、锁文件、bundle 选择与顺序。不另建绕过官方管理器的启用名单。
- Host：遵循目标版本支持的插件导出形式、`inject`、Config 校验及服务依赖语义；资源在官方生命周期内注册并清理，不用 Android 桥绕过依赖激活规则。
- Client：遵循目标版本 `dsh.client`、客户端导出、模块加载与外部依赖约定；使用官方 Slot 及真实 props，不替换应用根节点，不依赖跨插件 DOM 探测。React 等由官方提供的依赖按官方构建约定复用。
- 工具、事件及配置：以目标版本的 schema、输出、展示、事件模式和 Config 为准，不静默删减字段、吞掉错误或以旧契约伪造成功。
- 发行资源：遵循官方元数据、本地化、图标及资源导出约定，验证实际发布包包含运行文件与资产；安装成功不等于资源加载、插件激活或用户可见功能成功。
- 管理与重载：通过目标版本官方管理能力安装、启停和卸载；区分已保存、已激活、被覆盖、失败和需要重启。HMR 与包替换是否生效按官方结果验证，不承诺所有改动免重启。

#### 4.13.3 社区插件成功部署的验收链

部署链必须可观察：来源和版本确认 → 包解析/下载 → 依赖安装及构建脚本审批 → 官方 bundle 加载 → Host 激活 → Client 模块/Slot 加载（如有）→ 权限与设备能力检查 → 核心功能测试 → 停用/卸载清理。失败返回原始原因及所属阶段，不只报告“安装成功”。

兼容性按实际依赖分类：纯 JS/标准 Web 插件优先无修改验证；依赖桌面 API、Android 不可用二进制、特定 ABI 或原生绑定的插件明确标注阻塞或适配要求。官方插件标准兼容不代表所有桌面插件天然能在 Android 上运行；不得通过默认全权限、禁用文件锁或跳过构建错误换取表面成功。

建立代表性社区插件测试集，至少包括 Host 工具、Client 页面/Slot、配置/事件、stdio MCP、带原生依赖及设备能力扩展。对每个支持的官方内核版本验证首次安装、升级、重启、禁用、卸载与配置保留。未经测试不能概括宣称全部社区插件可用。

### 4.14 权限、多模态通信与版本扩展

#### 4.14.1 分层权限

区分 Android 系统授权、基座开放能力、DSH 操作审批及单次调用范围/有效期。插件声明能力不是授权，应用获授权也不等于所有插件可任意采集、外发或控制设备。用户可撤销授权、停止流与自动化；每次调用及持续任务均处理授权失效。

| 能力 | 必需对接与边界 |
| --- | --- |
| 文件 | 私有工作区、SAF 文件/目录选择、导入导出、持久授权检查；content URI 不当作 Unix 路径，默认不以所有文件访问作为前提。 |
| 网络 | 联网、连接状态、HTTP/WebSocket 与流式通信、代理、取消；网络存在不等于服务可达，联网不等于允许上传任意文件。 |
| 动作与传感器 | 摇动、姿态、旋转等语义事件；受限原始采样流。活动识别与普通运动传感器分别判断系统权限、硬件支持和版本限制。 |
| 无障碍 | 用户主动启用服务；节点观察、语义动作、手势、滚动和全局操作；不等于 Root、完整截图或绕过安全界面。 |
| 屏幕采集 | 单次截图/屏幕流与无障碍分别授权；遵守适用的 MediaProjection 同意和生命周期，安全内容不可承诺采集。 |
| 悬浮与通知 | 分别管理悬浮授权、通知权限及前台服务要求；权限失效准确反馈。 |
| 音视频与设备扩展 | 相机、麦克风、媒体、位置、蓝牙及传感器为首发必需实现，按需发现和授权，不提前索要全部权限；具体范围见下表。 |
| 系统行为与增强 | 分享、链接、剪贴板、振动及可选 Shizuku/Root；遵守前后台限制，不在失败后静默提权。 |

具体 manifest、运行时权限和后台限制根据最终 Android 范围与 targetSdk 核验，不能把单一版本行为推广到所有设备。采集、设备控制与向外部服务传输分别表达范围和用途；截图、界面文本、文件及音频不因已获采集权限就自动允许外发。

#### 4.14.1a 首发设备功能边界

| 能力 | 首发实现与正向证据 | 必需失败/停止行为 |
| --- | --- | --- |
| 相机 | 能力/格式发现、拍照、预览、录像，输出受管句柄 | 占用、拒权、撤权、旋转、后台限制、释放镜头；不能用空数据通过 |
| 麦克风与音视频 | 录音、播放、实时采集/消费流、格式协商与时间戳；验证合法消费者 | 拒权/撤权、背压、丢帧或中止策略、流取消；不自动外发，不承诺远端通话基础设施 |
| 位置 | 单次定位，用户显式启动的持续订阅及停止 | 定位关闭、超时、精度/来源说明、版本后台限制；持续订阅不等于允许后台定位 |
| 蓝牙 | 设备发现、连接生命周期；BLE 服务发现、特征读写和通知订阅 | Android 版本对应授权、关闭/断连、超时、取消、释放；不承诺所有经典蓝牙传输和专有设备协议 |
| 传感器 | 类型/频率发现，原始采样订阅、姿态/摇动等语义事件 | 设备无硬件、频率上限、撤订阅、背压、后台停止或另行授权 |
| Shizuku/Root | 检测、授权引导、受审批的增强任务和真实通道回执 | 未安装、未授权、服务停止、撤权和重启；基础 Agent 可在无增强通道时使用 |

持续采集需要系统可见指示及明确停止入口；相机、麦克风、定位、蓝牙与外发分别授权。硬件差异不假报成功。MuMu 无法证明的能力使用手机及所需外设补验；未取得正向证据不得标为该能力验证通过。超出上述范围的新用途另行决策，不无限扩大首发。

#### 4.14.2 无障碍观察—行动闭环

基座返回界面快照、窗口/显示器信息、节点引用及界面版本；插件提出动作后重新校验引用、授权和目标。优先使用语义节点，坐标动作注明坐标空间、方向与单位；窗口变化后拒绝过期引用。“已派发手势”与“目标操作成功”分开，执行后重新观察。

保留用户中止与高风险动作审批，限制循环动作和多插件抢占。支付、发送、删除、授权确认等不能因系统无障碍已启用而直接视为已获用户同意；系统安全限制与不可访问节点明确返回，不尝试绕过。

审批凭据绑定规范化操作、参数摘要、目标句柄及版本/内容标识、环境与启动轮次、实际权限通道、有效期和一次性执行标识。可信宿主展示待批操作，不接受插件自报 approved。执行前重新校验目标与授权；目标变化、环境切换、撤权、宿主重启或排队超时后，旧批准失效或重新确认。重新获得 Shizuku/Root 权限不自动续跑旧高风险队列。取消只停止尚可阻止的步骤；已执行或结果不确定的副作用如实报告，不用“已取消”伪装回滚。

基座提供的设备自动化通道禁止点击或操纵自己的可信审批界面；审批显示期间暂停冲突的自动化控制，受支持的平台上启用遮挡触摸防护。高风险确认无法判定可信用户交互时不自动执行，改走受支持的人工确认路径。此规则防止合作式自动化链自审批，不构成对同 UID 任意代码、外部恶意无障碍或 Root 的强隔离保证。

#### 4.14.3 统一控制面、多通道数据面

- 控制面：统一结构化请求/响应，保留 schema、请求 ID、环境、启动轮次、授权上下文、截止时间与取消语义。
- 事件面：设备、动作、任务等事件携带来源、序号、时间戳、有效期；支持订阅、取消、重连与有界缓存，明确丢弃/合并规则。
- 资源面：图片、音频、视频和诊断包使用受管资源句柄与元数据，通过独立文件/流传输，不向控制消息塞大体积 base64。
- 流式面：PTY、屏幕、实时音频和原始传感器流声明格式、采样率、背压、丢帧/丢样及终止原因，但不共享一条无差别释放规则。显示与媒体绘制随可见性暂停；观察订阅断连后取消或有界缓存并支持重连；Agent 作业与 PTY 后端按任务所有者存续，直到完成、明确取消或系统终止，GUI 隐藏、旋转和重载不自动取消任务。PTY 重连明确缓冲与输出截断策略，不承诺无限保留输出。录屏、音频及传感器采集按授权、系统前台条件和用途管理，撤权立即停止；确需后台采集时单独授权并满足系统限制。

传输可以按场景选择本地 socket、受认证 HTTP/WebSocket、Android IPC 或低频文件队列，由统一 SDK 屏蔽。不是要求首发同时实现所有传输，也不让各插件自行维护一套协议。端点认证与环境隔离不能仅凭 localhost 或插件自报身份；同 UID 任意代码的限制仍适用。

#### 4.14.4 官方版本适配与安全边界

官方 DSH 版本适配器、Android SDK、基座协议、原生能力模块及运行时分别版本化。启动协商协议主版本和必需能力；可选能力不支持则局部降级，必需能力不兼容明确阻止对应功能，不静默改写官方插件契约。

官方接口变化优先由版本适配层处理，避免所有社区插件与基座一起修改；适配层只映射受支持能力，不假造不存在的事件或服务。破坏性协议升级提供明确迁移/拒绝策略，维护官方 DSH × 基座 × 运行时 × Android 的兼容矩阵与契约测试。

原生模块预留受控注册位置，不等于允许插件加载任意原生代码。新增系统能力涉及 manifest 或 Kotlin/native 实现时仍可能需要 APK 更新。第一版以可信插件为前提；同进程/同 UID 下的插件级权限是合作式约束，不能宣称能隔离恶意插件。运行不可信插件需要另行设计更强的身份或执行隔离。

## 5. 插件、配置与数据

### 5.1 归属原则

- 程序版本可替换，用户数据不能作为安装资产反复铺设。
- 默认模板只用于初始化缺失内容，不覆盖已有用户选择。
- 引擎必需官方组件随内核版本交付；用户扩展插件放在所属环境的持久化插件区。
- 插件代码和插件设置分开管理。
- profile 的依赖清单、锁文件、bundle 启用名单及顺序、patch 均须保护。
- 修复模型配置独立持久保存，可选强模型，不依赖日常插件才能调用。
- 模型配置跨环境迁移通过显式导入完成，不直接共享整份可写配置。

### 5.2 建议目录与版本归属

以下是拟议结构，不是已验证的 DSH 默认目录；启动参数、实际 profile 布局及包解析行为须在原型中核对。

```text
应用私有持久化区/
├─ runtimes/<版本>/             受管 Node、必要工具与兼容库，按版本封存
├─ toolchains/<环境>/<版本>/    用户工具链独立前缀，不覆盖受管运行时
├─ kernels/K1/<版本>/           一号官方 DSH 完整依赖树
├─ kernels/K2/<版本>/           二号已验证官方 DSH 完整依赖树
├─ environments/A/home/         日常 DSH_HOME；内含所属 profile 与插件
├─ environments/R/home/         修复 DSH_HOME；精简插件与独立模型配置
├─ environments/E/home/         应急 DSH_HOME；精简插件与独立模型配置
├─ workspaces/                  用户项目
└─ supervisor/                  实例状态、启动轮次、日志、快照及恢复事务
```

每次启动形成实例描述：环境 ID、内核版本、运行时版本、DSH_HOME、profile、工作目录、服务地址、桥接上下文和启动轮次。监督器据此管理进程，不依赖全局固定端口、固定 profile 或模糊进程名。

K1/K2 使用独立完整依赖树；A/R/E 的可变插件与配置独立。升级部署到新的版本目录，不覆盖正在运行的目录；试启动与提交按第 6.5 节联合事务执行，不能只以目录指针切换代表更新成功。

激活记录绑定内核版本、运行时引用、profile 执行状态 revision（依赖清单、锁文件、包实体或可恢复内容引用、bundle 顺序及 patch）、配置版本和数据迁移状态。用户设置仍属持久数据，但涉及执行兼容的迁移必须进入同一事务。更新、修复与快照进入监督器管理锁；官方包管理、构建脚本和 HMR 是否能参与锁必须先验证实际接缝，不能假定官方已有 Android 事务接口。在线协调不足时采用维护窗口：冻结新入口，等待或经用户确认停止相关任务，停 A 及写者，取得一致性点并对账。直接命令绕过入口也须停止并检测漂移。必要接入补丁遵循第 4.8 节，不改官方安装语义；无法确认一致则拒绝。

### 5.3 A 用户配置与插件整目录加密备份、导出与导入

#### 5.3.1 原样范围与操作入口

- 备份对象为 A profile 和对应插件存放目录的完整目录树，以及清单明确列出的 A 关联设置/受管素材。直接从一致快照归档，不仅保存安装清单，不对插件文件逐项脱敏或任意裁剪。保留文件内容、相对目录、必要权限与链接元数据，包括目录内点文件和完整依赖实体。
- 目录内可能含 API Key、token、Cookie 或其他秘密，用户已选择用自设密码加密完整备份。范围内文件原样进入加密载荷；首次设置与导出时明确提示“持有包和密码即可读取这些秘密”。这不是公开诊断包。
- 先解析实际安装布局：pnpm store、符号链接、外置素材或配置不一定在插件目录中。只记录链接不代表备份完整；属于插件执行闭包的外部实体经路径映射与允许列表纳入，禁止盲目追随链接卷入任意用户文件。缺失闭包、不可归档特殊文件或读失败均须逐项报告，部分包不称完整成功。
- 全量是上述目录范围的全量，不是整个设备或 DSH_HOME 全量。R/E、工作区、聊天会话、用户工具链、K1/K2、运行时、诊断日志与范围外缓存不默认进入用户包；目录内文件不因名称像缓存就静默跳过。外部必要版本及未纳入项目写入清单。backup 不能位于被归档源内。
- 全局账号存储、Android Keystore 密钥和系统授予的权限不因插件整目录而自动成为可迁移对象。范围外账号恢复按官方流程重新认证；范围内旧凭据也受退出/撤销规则约束，不能承诺恢复即获得有效授权。
- 日常操作仍统一放在官方插件设置“安卓基座”：用户设置/更改密码、选择 backup 目录、自动备份状态、立即备份、导入、导出/分享、最近成功与失败原因。不新增原生日常设置中心。最小原生恢复出口允许故障时选择加密包并输入密码。
- 设置插件负责交互，原生备份器负责一致性快照、加密、校验、SAF 发布、轮换与持久状态。A 因维护暂时停止时，由已加载设置 Client 与受认证原生桥承载进度，不依赖已停止的 DSH 后端继续响应。

#### 5.3.2 用户密码与加密契约

- 密码由用户设置并二次确认，不使用固定密码，不由 AI 保管，不写日志、profile、包 manifest 或导出记录。忘记密码且无可用本机解锁材料时不能恢复；不能用 Android Keystore 代替可跨设备输入的密码。
- 首次启用必须完成目录授权与设密。为支持以后自动备份，经明确告知在本机仅持久化由 Android Keystore 包裹的备份密钥材料，不保存明文密码；每个备份仍须能单靠用户密码在重装/其他兼容设备解密。锁屏/重启后密钥暂不可用时等待允许的解锁时机或提示失败，不降级明文。
- 加密实现复用维护中的密码 KDF 与认证式流加密库/容器，不自创密码学算法，不把普通 ZIP 或仅“设置打开密码”当作已满足。阶段 G4 冻结库版本、KDF 成本上下限、随机盐、认证加密格式、nonce/分段规则、头部认证与截断检测；实施前完成独立往返和篡改实验。
- 文件名、清单及内容哈希置于加密载荷；外部头只保留解析必需的格式/KDF 参数与随机信息，不泄露插件列表或秘密。限制未认证头的 KDF 和内存参数，避免导入包诱发资源耗尽。密码、盐及 nonce 的处理按选定库规范，不复用不允许复用的参数。
- 归档压缩后流式加密，不能把全包读进 RAM；公开 SAF 目录从不留下明文中间包。私有明文快照仅按最小所需生命周期保留，任务结束/对账后清理；不宣称闪存删除等于物理安全擦除。
- 密码变更对新备份生效；旧包仍需要旧密码，界面明确标识，不暗中重写旧包。若提供重加密，作为单独受控任务，验证新包后才处理旧包。Keystore 丢失/失效时由用户重新输入密码恢复自动备份能力，不清空已有包。
- 自带哈希只能用于完整性核对，不代替认证加密；加密也不证明插件可信。导入通过密码校验、整包认证、清单与展开安全检查前，不执行插件、脚本或提交配置。

#### 5.3.3 backup 目录、发布与三份保留

- 用户通过 SAF 目录选择器授权可跨卸载保留的父目录，应用在其中创建 backup；不能使用 app-specific 目录冒充卸载后保留。重装后重新取得 URI 授权，不能假定授权跨卸载保留。
- 采用唯一 ID 与时间戳命名，例如 `A-profile-20261022-220000-<id>.dshbak`；后缀为本项目容器候选，最终格式在 G4 锁定。受认证清单包含源范围、完整/部分标志、依赖闭包、DSH/Node/ABI/配置版本、profile revision、创建时间及文件哈希，不依赖外部文件时间排序。
- 自动和手动共保留最近三份“完整、加密、验证且发布成功”的 A 包。新包完整提交后才能删除最早所属成功包；失败/取消/部分包不挤占这三份。部分包和临时产物另行限量清理，不能无限积累。
- 仅清理应用账本与完成清单确认归属的包，不删除用户其他文件或单独导出副本。SAF 不保证原子重命名，采用临时输出与可对账的完成标记；最终名称或文件存在不代表可恢复。
- 以密文摘要、长度及选定格式的认证检查验证写入；若提供方不支持必要读回验证，不报告完整成功。第四份空间应在开始前预检；清理失败提示并保留可恢复包，不以破坏旧包强行满足三份上限。
- 未设密码/目录、锁定密钥不可用、空间不足、断权、提供方离线或读回失败，记录明确状态。禁止静默存到私有目录后声称具备卸载恢复能力。异常重启先对账临时、已发布和待清理记录。

#### 5.3.4 每次成功进入后自动备份与手动备份

- 用“成功进入 A 的启动事件 ID”去重：A 服务与必需桥通过就绪检查，官方页面完成连接归属确认后，每个新的正常进入事件安排一版 A 自动备份。不要求远端模型网络或账号登录可用才允许备份；R/E 不作为用户备份对象。
- 页面刷新、旋转、短暂断连/重连、普通回前台不新建事件；一次备份为取得停写点而暂停/重启 A，属于同一事件的维护续启，绝不再次触发自动备份形成循环。监督器持久记录 origin、eventId 与 pending/running/succeeded/failed 状态，崩溃后先对账，不重复发布。
- 首次成功进入时若尚未设置密码与目录，在“安卓基座”引导完成，再执行该事件的待办备份。用户未设置时应用仍能使用，但该次明确标为未完成，不伪报成功或永久静默关闭自动备份。
- 自动备份不静默终止正在运行的任务。存在任务、安装、HMR 或未知写者时等待或由用户确认进入维护；等待有界且可见，无法安全取得一致点则标记失败/受阻并支持手动重试，不无限阻止使用。
- 可靠首版流程：登记管理事务 → 冻结管理入口 → 等待/确认停止写者 → 停 A 并确认后代/代理状态 → 在私有区取得一致快照 → 恢复原组合与页面 → 对快照流式压缩加密 → SAF 验证发布 → 三份轮换。能在线快照的替代实现必须另有一致性证据，不能边写边压缩。
- 自动备份的失败不等于 A 启动失败，不触发 R/E 切换，不反复重启；状态显示最近完整成功时间和本次失败原因。快照已取得后 A 可继续任务，不为大包压缩长期停机；UI 明确哪些阶段允许取消。
- “立即备份”使用相同流程，可与尚未开始的同 revision 自动请求合并，但不得把尚未成功的请求说成已有新版本。退出不再强制生成备份，后台强杀/系统回收不承诺备份回调；下次启动对账并处理新的正常进入事件，不追造退出包。
- 秘密、快照、候选和原生恢复保留预算共同参与空间预检；无足够安全空间时拒绝本次任务并保留旧完整包，不跳过一致快照。

#### 5.3.5 导入与恢复

- 正常路径先启动可用 DSH，在“安卓基座”选择包并输入密码；A 无法运行时使用最小原生恢复出口。输入错误、锁定密钥缺失、篡改、截断、未知格式与超限参数分别明确报错，不泄露密码或秘密内容。
- 在私有暂存区完成解密认证与清单检查；限制总展开量、文件数、单文件大小、路径深度和解压比；拒绝穿越、危险链接、冲突条目及校验后换文件。认证不完整的暂存内容不得激活，导入不直接覆盖当前 A。
- 展示包时间、插件组合、范围、完整/部分、ABI/Node/DSH 兼容性、缺项、密码世代提示和替换影响，经确认后停写并给当前 A 建立恢复点。按原安装图恢复目录、依赖实体和安全链接，不盲目混合两套依赖图；R/E、工作区与聊天会话不被误覆盖。
- 在候选副本核验并按第 6.5 节事务提交。目录完整不保证跨 ABI/Node 可执行；原生依赖重建、脚本或联网重新安装仍需分别批准。Android 系统权限、Shizuku/Root 与采集授权重新检查，备份里的“曾获授权”字段不构成当前授权。
- 加密包可能包含有效秘密，导入须视作敏感高风险操作。尊重本机退出/撤销记录；无法证明旧登录仍可安全恢复时重新认证，不能回滚账号退出。恢复密码不等于服务端授权恢复。
- 失败保留当前 A 与原包，清理未提交明文副本并报告阶段；成功分别报告文件恢复、插件激活和功能验证，不以“已解压”冒充全部恢复成功。

### 5.4 持久化边界

原生应用私有区与用户授权的备份目录分开；下述 `backup/` 不放在可卸载清除的应用私有区或 app-specific 外部目录中。

插件运行目录不默认放在公共下载目录，也不放在可替换的内核版本目录中。正常同包名、同签名覆盖安装应保留用户数据；卸载应用通常会删除私有数据，需要独立备份和导入导出方案。

插件长期保存不意味着跨内核版本必然兼容，仍须检查 DSH 接口、Android 架构及 Node 原生绑定要求。

## 6. 故障判断与恢复

### 6.1 判断原则

启动包含插件加载，不能用“进程启动失败”直接判定内核坏了。必需插件失败可能终止启动；可选插件失败可能仍保留主要功能。

基座记录启动阶段、诊断、退出原因和服务就绪信号。白屏或超时只能说明未就绪，不能独立证明内核损坏。

### 6.2 分层诊断与启动体检

分别记录进程存活、DSH 服务就绪、Web 页面加载、Android 桥可用四层状态，并保存启动阶段、退出码、有界脱敏 stderr、目标版本与启动轮次。页面白屏而服务正常时优先恢复页面或关闭界面增强；模型服务网络失败不直接触发内核切换。

秘密保护优先于保留原始诊断：普通持久日志在采集时限长与脱敏，敏感字段不记录；诊断导出再次检查，不自动包含凭据快照。确需原始诊断时，仅经明确授权使用受控、短生命周期缓冲，不自动持久化或外发。对任意插件文本不能保证完美秘密检测，因此同时限制采集字段、访问与导出范围；脱敏损失应可解释，保留必要的错误类型和阶段。

启动体检复用目标版本自身的 `--dump-config`/profile 解析，不在 Kotlin 重写 YAML。前轮评审发现锁定版本会调用 prepareProfile，并可能重写 profile 配置、规范化 manifest 或清理链接，因此不得直接在原 A 上把它当只读命令运行。先确认停写并复制完整受测布局到诊断副本，在副本运行，记录规范化差异并验证原 A 哈希/元数据未变；命令也可能加载执行代码，须保持可信插件及受限副作用边界。配置转储不能证明插件激活、服务或工具可用。

DSHAPP 救援文档记录：第三方 bundle 被跳过、核心必需条目缺失时，配置转储也可能返回 RC=0。因此体检须结合退出码、诊断信息和与目标版本匹配的必需组件检查；不能固定照搬另一版本的插件 ID 清单。

体检对原 A 保持只读，诊断副本可变更但不得回写；保存现场，不自动改名、摘除插件或重解包 A。需要修复时先进入 R/E，再按授权事务执行。可选插件启动失败应尽量局部降级且记录原始错误，不能静默消失；但注册时异常保护不等于处理了加载、异步激活或调用阶段的全部故障。

### 6.3 恢复链

| 情况 | 处理 |
| --- | --- |
| A 正常，仅可选插件异常 | 保留可用功能并提示，提供修复入口，不强制切换。 |
| A 无法就绪或关键功能不可用 | 保存现场，停止并确认进程退出，再启动一号内核的 R。 |
| R 能运行 | 留在 R 诊断 A，不重置 A。 |
| R 无法就绪 | 启动二号内核的 E。 |
| 明确确认一号文件损坏等故障 | 可直接进入 E。 |
| E 也无法运行 | 留在原生恢复页，不无限重启。 |

R 能否运行是主要分流依据之一，而不是强行把内核启动和插件加载划成互不关联的两个阶段。

### 6.4 修复安全

- 默认只读诊断，修改前确认授权并备份。
- 保存完整插件组合与配置快照，优先隔离具体问题项。
- 修复前声明允许修改的受管范围及恢复方式，只对具备一致快照和可恢复依赖的范围承诺撤销；失败保留现场并可继续进入修复环境。外部工作区、Root 系统更改及服务端副作用另行审批，不承诺自动撤销。
- 快照 manifest 记录配置、启用组合、锁文件、实际包实体或可恢复引用、链接目标与哈希，并冻结相关包管理、HMR、构建脚本及后代写者后建立一致性点。离线恢复所需包不能只保存在线下载地址。
- 凭据备份与普通诊断分离；恢复尊重用户退出与授权撤销记录，不以恢复旧快照自动复活账号会话，服务端状态不确定时重新认证。
- 不允许多个实例同时修改 A。
- 二号是修复工具环境，不是直接接管新版日常数据的旧版 DSH。
- 旧内核不得直接写入不兼容的新版会话数据库；代码回滚与数据回滚分别处理。
- 模型不可用时仍提供日志、备份和还原入口。

### 6.5 管理事务与故障边界

本节为拟议运行与恢复契约，不是现有实现。首版先落实所有权、单写者、持久转换和恢复决策；具体锁实现、磁盘持久化机制、配额数值及接口签名由原型确定，不借讨论稿承诺未经验证的平台能力。

#### 6.5.1 资产归属与写入表

| 资产 | 管理者与允许写者 | 版本与一致性边界 | 快照及清理规则 |
| --- | --- | --- | --- |
| 基座 APK 与原生恢复代码 | Android 安装机制与可信发布流程；普通插件不通过 SDK 修改 | APK 版本、签名及原生能力版本；升级前后核验救援组合，不假定可以降级 APK | 不把 APK 回退当作内核回滚前提；保留可信恢复包来源与原生导入入口 |
| 受管运行时、K1/K2 与必要适配资产 | 基座部署器；日常包管理不原地写入 | 版本、兼容清单和最终文件树哈希；封存目录仍非同 UID 安全边界 | 被激活记录、救援组合或恢复点引用时不得回收 |
| 用户工具链 | 所属环境的工具安装任务，经受管管理入口协调 | 独立前缀与版本记录；显式 PATH/库解析，不覆盖受管依赖 | 恢复所需实体或离线可恢复引用入清单；可再生缓存与必要包区分 |
| A/R/E profile 执行状态 | 所属环境的官方包管理与经授权修复；候选在副本中写入 | 依赖图、锁文件、包实体、bundle 顺序、patch 与 revision 一起绑定激活记录 | 冻结写者后快照；候选不得覆盖运行期间产生的用户变更 |
| 用户配置、会话与凭据 | 所属 DSH 环境；迁移由受管事务协调 | 配置/schema 版本、迁移状态与一致性点；秘密单独保护 | 备份不等于默认可导出；账号恢复尊重退出/撤销，不复活旧授权 |
| 用户目录 backup 中的 A 加密整目录包 | 原生备份器；每次成功进入 A 调度，设置插件提交手动/导入请求 | 一致 profile revision、完整插件目录/依赖闭包、原样配置、加密清单；可能含秘密，不含 R/E | 用户设密；自动/手动共保留最近三份完整成功包；新包验证发布后才清理旧包，跨卸载重新授权 |
| 用户工作区与外部系统 | 用户任务及单独获授权的操作 | 不默认加入内核更新回滚；任务副作用单独跟踪 | 需要备份时显式声明；外部发送、服务端操作与 Root 修改不承诺自动撤销 |
| 监督元数据、事务与激活记录 | 唯一监督器；UI/插件只提交管理请求 | 转换 ID、阶段、epoch、目标及恢复点持久记录 | 限量保存历史但不提前删除未完成事务及其恢复引用；日志脱敏 |
| 悬浮素材、采集流与观察订阅 | 基座资源管理器；按环境/扩展归属 | 配置 revision、资源句柄、租约与有效期 | 按各自生命周期释放，不将 GUI 断连等同于执行任务取消 |

#### 6.5.2 单监督器与管理锁

- 启动、停止、A/R/E 切换、更新、修复、恢复和受管包操作由同一监督协调机制受理。使用跨进程监督锁及必要的环境写锁；同环境冲突操作串行，不无差别阻塞全部普通任务。锁顺序与取消规则在实现前明确。
- 持久记录 desired/observed 状态、转换 ID、管理 epoch、源/目标环境、实例身份及阶段。进程身份须能区分 PID 复用，跟踪受管后代、后台任务与外部权限代理作业；不能只按进程名或父 PID 猜测。
- 切换前冻结新管理写入、使旧桥租约与请求 epoch 失效，再请求停止。epoch 仅约束经过网关的请求，不阻止仍在运行的任意代码直接写文件；确认相关作业退出或可靠停止写入后，才允许修复。
- 宿主重建后先取得监督权，再对账磁盘记录、实际进程、事务与激活组合。进程状态不明、锁无法确认或停止超时时，进入只读恢复，不盲目杀进程或启动第二个可写实例。
- 状态记录采用受验证的原子发布与持久化顺序，恢复时能区分未完成、已提交及损坏记录；仅写 JSON 或改名不能自动证明断电一致性。存储语义与异常处理须通过 Android 真机故障注入确认。
- 用受管作业账本、启动身份（含可用的进程出生标识）、PTY/进程组与权限代理停止回执对账；覆盖 setsid、双重 fork、宿主死亡与 PID 复用。不能核验的进程不得按名称误杀。只读恢复还必须提供活性出口：提示系统强制停止本应用或设备重启，再由原生入口重新核验；确认干净后才允许恢复写入。外部 Root/代理作业仍单独确认，重启本应用不自动证明它们停止。

#### 6.5.3 状态转换与重启决策表

以下阶段名表达契约，不要求实现照搬 API 名称。每步先记录足以恢复的意图，关键副作用后记录结果；提交标记与激活记录必须具有可判定的一致关系，不能维护两个无关联的“当前版本”。

| 转换/阶段 | 前置条件与持久记录 | 成功条件 | 失败与宿主重启后的动作 |
| --- | --- | --- | --- |
| 切换：QUIESCING | 持监督锁，记录源/目标、转换 ID、新 epoch；冻结旧入口并发出停止请求 | 旧受管作业树及相关写者已确认停止 | 对账而非信任“已请求停止”；无法确认则只读恢复，不向 A 写修复 |
| 切换：STARTING | 保存目标组合、启动身份、地址与轮次；不复用旧授权 | 服务及必需桥就绪，页面连接归属可确认；页面故障单独处理 | 清理可确认的失败实例，按有界规则降级；旧页面不得控制新实例 |
| 切换：ACTIVE | 提交唯一激活记录与已观察状态 | 一个激活环境，页面/认证/桥一致 | 对账实际实例后继续或恢复，不因未完成切页重复启动 |
| 更新：PREPARED | 校验兼容、空间、归档与候选树；锁定旧组合和恢复引用 | 候选封存，旧组合未被覆盖，具备恢复条件 | 可丢弃候选；保留旧组合。不可清理唯一救援组合 |
| 更新：DATA_READY | 冻结相关写者并建立一致快照；迁移仅在候选副本进行 | 内核、profile 图、配置与数据副本对应同一候选 revision | 迁移失败只放弃副本；无法隔离或备份则拒绝自动迁移 |
| 更新：TRIAL | 候选使用独立 HOME、工作目录及桥上下文，不接真实用户写入；无外部副作用授权 | 候选通过服务、插件与必要能力检查；记录验证结果 | 终止候选并保留旧组合；安装脚本、联网/设备操作也属副作用，不能只换 HOME 就视为隔离 |
| 更新：COMMITTING | 再确认原状态未漂移；持写锁记录提交意图，停止候选与旧写者，确定新组合 | 激活记录与提交结果可恢复地指向同一完整组合 | 依据持久提交点恢复完整旧组合或新组合；无法判定则只读恢复，不跨 schema 启动 |
| 更新：COMMITTED | 记录新激活组合及首次开放真实写入的边界 | 新环境接管，旧组合按引用策略保留 | 已有新写入后不自动恢复旧快照；仅兼容降级或经授权处理数据，不能静默丢弃已确认写入 |
| 修复：SNAPSHOTTED → APPLIED | 目标停写、快照完整、修改允许列表及审批有效；记录执行步骤 | 受管修改可验证，必要时按声明范围还原 | 不确定副作用如实报告；保留恢复点，外部动作不能假装被文件快照撤销 |

试运行不是恶意代码沙箱：首版可信插件前提下，候选须使用受限授权上下文、明确控制外部访问并检查副作用；若外部适配及第 4.8 节允许的最小补丁仍不能可靠约束候选副作用，则缩小验证范围、停止自动试运行或转为另行授权的维护流程，不能声称已隔离。A 在准备期可以继续运行，但建立一致性点后须冻结；检测到 profile/数据 revision 漂移时重新准备，不用旧副本覆盖新变更。

#### 6.5.4 原生恢复生存预算

- 统一统计受管任务/子进程数量、日志、下载、缓存、候选部署、快照和保留版本；首版即定义上限、磁盘低水位及清理次序，数值在设备原型中确定。对任意同 UID/Root 进程不宣称具备操作系统级资源强隔离。
- 为最小事务记录和恢复操作保留应急空间预算，E 尽量保持已部署可启动，不能依赖故障发生后才解包。预算和预留方式须验证，不能仅靠报表数字声称空间必然可用。
- 低水位拒绝新增部署、快照或大任务，优先清理可再生缓存和轮转日志；不得回收唯一救援组合、未完成事务依赖或唯一有效恢复点。无法安全快照时转只读，不绕过快照直接修复。
- 内存压力和任务扇出时优先暂停/终止非关键媒体与任务，保护监督控制面；不能承诺 Android 永不杀进程，重点是系统回收后仍能走无扩展原生恢复和事务对账。

以下均为待执行验收，不代表已经通过；先完成最小官方 GUI、一个标准插件及 A/R/E 路径，再扩展媒体和设备能力。

| 故障注入 | 必须保留的能力或结果 | 必须拒绝的行为 |
| --- | --- | --- |
| A 工具链安装失败、替换用户依赖或中途断电 | E 固定运行时哈希不变且可启动 | 日常包管理覆盖受管运行时 |
| 升级基座后断网并损坏 K1；改变 Node ABI/桥协议 | 至少一个完整救援组合可运行；不兼容发行不能宣称升级成功 | 先破坏唯一应急组合再要求联网补齐 |
| 在停止、启动、切页阶段杀死宿主；保留孙进程，模拟 PID 复用与并发入口 | 重启先对账，最多一个管理事务，不误杀；故障可进入只读恢复 | 未确认旧写者停止即修复 A；旧 epoch 请求提交 |
| 在准备、迁移、试运行、提交阶段中断；同时触发包管理/HMR | 完整旧或新组合可判定，依赖图与数据版本一致 | 只切代码指针、跨 schema 写入或覆盖运行期新变更 |

| 损坏持久媒体、渲染进程退出、可选能力初始化崩溃 | 无 Node、无扩展路径仍可进入原生恢复并停用故障模块 | 每次启动无限重载故障模块 |
| 构建写满盘、日志洪泛、内存压力、子进程扇出 | 可重新进入原生恢复、停止故障任务并查看最小脱敏诊断；可写条件满足时导出 | 为继续更新而删除唯一救援组合；无快照强行修复 |
| 审批后替换文件/窗口、切换环境、撤权重授权或重启 | 执行前拒绝旧批准或重新确认；结果不确定明确报告 | 错目标执行、自动提权续跑、自动化点击本应用审批 |
| 路径穿越、危险链接、重复条目、解压炸弹及校验后换文件 | 不越界写入，不启动未验证内容，旧组合保持完整 | 在可变未封存候选目录直接运行 |
| GUI 隐藏、旋转、重载或断线；撤销录屏/音频授权 | Agent/PTY 任务可继续并重连；采集在撤权后停止 | 把 GUI 断线当作任务取消或继续无授权采集 |
| 向 stderr/嵌套错误注入假 token、Cookie 和授权 URL | 普通日志及诊断导出不含测试秘密，保留错误阶段 | 自动持久化/外发原始秘密或导出凭据快照 |
| 并发安装时请求快照、删除旧包后恢复、退出账号后恢复旧快照 | 写者冻结或快照被拒绝；可还原声明的依赖；账号保持撤销或重新认证 | 不一致快照、仅恢复 manifest 就报告成功、复活已撤销登录 |

## 7. 与官方恢复机制的关系

核对的官方 master 提交为 `687f282e8625c6b8d11ff58211a90524be2e4317`，不代表所有已发行版本行为一致。

该版本 Desktop 原生恢复提供退出、重启、禁用第三方插件选项。普通重启不执行禁用；对应恢复操作会：

1. 保留已安装插件包、依赖声明及其他 manifest 字段。
2. 改写启用的 bundle 列表。
3. 将 profile patch 重命名为带时间戳的备份，下次初始化创建空 patch。
4. 不修改 home 级 patch。

核对的恢复函数没有同时保存旧 bundle 启用名单，因此“包还在”不等于“原来的组合仍可一键恢复”。

本方案默认由宿主切换 R 或 E，不先对 A 执行清理式恢复。如需调用官方恢复函数，应先备份完整 manifest、启用名单与顺序、patch 和相关配置。

`--from-default-profile` 是创建或替换自定义 profile 的操作，不作为无损救援开关。

## 8. 三类发行产物

| 产物 | 用途 | 内容 |
| --- | --- | --- |
| 全量安装 APK | 首次安装、完整离线部署 | 基座、配套运行时、一号内核、二号应急内核及初始化模板。 |
| 基座升级 APK | 已有用户升级安卓层 | 完整可运行的新基座和必要运行时，省略可独立保留的 DSH 内核载荷。 |
| 内核升级包 | 在兼容基座上更新日常内核 | 一号 DSH、配套依赖、前端与兼容清单，不默认更新二号。 |

### 8.1 APK 规则

- 两类 APK 是同一个应用的不同发行载荷，使用相同包名、签名体系和一致的 versionCode 规划。
- 基座升级 APK 不是局部补丁；Android 会替换安装内容，必须保证其自身完整可运行。
- 首次安装后将内核部署到私有持久化版本区，不能仅存放于旧 APK 内。
- APK 升级不得重新覆盖用户配置、插件或已安装内核。
- 基座包误用于首次安装时，提供原生内核导入或下载引导，不能白屏。
- 新基座安装前尽可能预检，启动内核前强制检查兼容性。APK 发布准入须验证至少一个完整救援组合；运行时、原生库、桥或界面适配变化时，保留旧兼容资产或交付匹配新组合，不把“拒绝启动旧 E”当作救援通过。
- 普通 APK 安装不能假定可随时降级或由应用自行拒绝已完成的安装。旁加载绕过应用预检时，首次启动先核验现存组合；发现不兼容不破坏原文件，使用不依赖 DSH 的原生恢复入口导入/部署可信兼容组合。该兜底不替代发行前断网救援测试。

### 8.2 内核更新规则

- 全量 APK 的内核载荷与独立内核包使用同一构建产物。
- 声明架构、Android 范围、基座版本、Node 和原生依赖要求及数据迁移要求。
- 明确发布信任根及密钥更新规则；签名版本清单绑定文件列表、哈希、展开尺寸与目标兼容要求，哈希本身不代替来源认证。
- 在独立暂存区解包；拒绝绝对路径、路径穿越、重复/冲突条目及越界 symlink/hardlink。必要内部链接须验证最终目标与整条解析链，不能一概禁用而破坏正常包结构。限制总展开量、文件数、路径长度和单文件大小，防止解包耗尽资源。
- 校验最终文件树后封存，防止受管流程在验证与使用之间替换内容；激活前核验引用。封存不构成同 UID 恶意代码隔离，不从可变下载/暂存目录直接启动。
- 部署、候选迁移、试运行与提交遵循第 6.5 节联合事务，不以原子目录切换替代代码/profile/数据的一致提交。
- 不兼容则拒绝，必要时要求升级基座。
- 保留可恢复的旧组合；迁移前建立一致备份。提交前失败放弃候选，提交后已有新写入则按兼容性与明确授权恢复，不静默覆盖新数据。不可逆迁移或无法快照时拒绝自动回滚；历史可信版本的授权回滚与一般包降级策略分别定义。
- 二号独立低频验证更新，不随一号无条件替换。
- APK 内置内核仅作为初始化和恢复来源，不能每次启动强制重铺或静默降级现有内核。

关键验收：全新安装版本 V 与从旧版升级至 V，应获得一致的目标内核文件和默认能力；用户数据差异不应造成程序载荷分裂。

## 9. 复用范围

### 9.1 官方 DSH

复用 Agent 执行、工具编排、子代理、会话、官方 Web GUI、profile、插件管理、启动诊断和版本兼容检查。

### 9.2 DSHAPP

借鉴 Termux bootstrap、Android Node、原生绑定编译、文件兼容层、PTY、Web 容器、后台保活、日志及原生桥。

以上属于复用方向，不代表现有代码可直接搬用。必须审计写死的包名、路径、端口、资产解包和单实例假设。现有等长 ELF 路径替换及低 targetSdk 方案形成实际约束，不能未经验证直接更改。

### 9.3 AndriodTablet 分支

参考仓库为 `yunhesi-wind/DSH-plugins`，准确分支名为 `AndriodTablet`，不是官方 DSH 仓库的同名分支。

- `plugins/android-layout-preferences/index.js`：保存 `layoutMode` 与 `lastLayout`；无客户端入口，不执行布局。
- `native-adapters/dsh-android-mobile`：APK 配套实际布局适配器归档；由宿主加载，不作为普通 profile bundle 再安装。
- `native-adapters/tests/auto-layout.test.mjs`：验证比例阈值、边界保留、手动锁定、无效尺寸、历史写回与卸载等策略。
- `plugins/dsh-mobile-composer-layout/lib/client.js`：跟随实际手机布局，提供输入区、顶栏、设置页三个独立开关；退出布局时撤销效果。当前开关保存在设备 localStorage，不等同 profile 配置；端口、浏览器内核或 Web 存储分区变化时不得假定自动继承，应定义迁移或重新设置策略。

DSHAPP 的“双 Web 内核”指系统 WebView 与 GeckoView，现有发行使用不同 applicationId 的两个 APK；本项目“双 DSH 内核”指独立版本依赖树。两者不是同一维度，本方案未决定将两个 Web 内核同时集成进一个 APK。

### 9.4 不照搬

不继承小改动必须整包更新、升级覆盖用户目录、清理后丢失插件组合的做法。不以假终端、禁用锁或默认全权限换取表面兼容。用户态写拦截不能直接宣称具有桌面内核沙箱的隔离强度。

## 10. 验证策略

电脑 Android 模拟器用于多系统镜像测试；普通桌面虚拟机不能单独替代 Android 验证。

矩阵至少覆盖：

- 最低支持版本、关键系统行为变化版本和最新目标版本。
- 正式发行架构载荷；x86_64 模拟器通过不证明 ARM64 可用。
- 全量首次安装、全量覆盖、基座升级、内核升级和不兼容拒绝。
- 子进程、PTY、锁、Git、包管理、网络、MCP、子代理、后台任务和取消。
- 升级后模型配置、插件、启用组合、会话和修复设置保持。
- A 插件或配置损坏后进入 R，一号程序损坏后进入 E，均保留 A。
- 更新中断、空间不足、校验失败、修复失败与回滚。
- Shizuku / Root 未授权、可用、撤权和服务停止等状态。

发行前仍需代表性真机覆盖厂商后台管理、系统 WebView、功耗和权限差异。

## 11. 首发验收追踪矩阵

1. 基座可独立启动 A、R、E，停止逻辑不误操作其他进程。
2. A 故障后 R 可使用独立保存的强模型配置。
3. 一号损坏后 E 可运行，且不依赖一号可变目录。
4. 救援不自动重置 A 的插件和自定义配置。
5. 修复前建立声明范围内的一致快照，失败可在该范围恢复，不产生循环重启；外部和不可逆动作不得报告为已自动撤销。
6. 基座更新和内核更新均不覆盖用户资产。
7. 两套 DSH 都不能启动，或共享 Node 无法运行时，原生恢复入口仍可用。
8. 旋转、分屏、浮窗与开关键盘不丢草稿、不重建会话；自动布局严格遵循阈值和滞回区间，IME 不误触发布局切换。
9. 退出手机布局、关闭模块或卸载适配后，样式、事件、观察器与借用控件可正确清理；不兼容前端版本能退回官方界面。
10. 服务正常但页面白屏时走页面恢复，不误判为内核损坏；可选插件异常不无条件升级为整个环境切换。
11. A/R/E 切换后页面、认证和桥接归属正确，旧启动轮次请求被拒绝；启动超时后不会无限重启。
12. 同包名同签名 APK 升级、独立内核升级与回滚，不覆盖插件组合、模型配置、会话和工作区；不兼容的数据迁移不允许只回滚代码。

13. 悬浮窗支持授权、显示隐藏、拖动缩放、贴边折叠、面板及焦点切换；权限撤销或用户关闭后准确报告不可见，并保留可用的非悬浮恢复入口。
14. 使用本项目新 SDK 验证动作池、随机链、透明动画、点击/拖动回应、抛掷碰撞、自动移动和状态提示；不以原 pet 插件直接运行作为要求。
15. 透明视频不支持、素材缺失、解码失败或内存不足时局部降级；隐藏、锁屏和节能时停止不必要的绘制、解码和物理循环。
16. A/R/E 切换、插件停止/卸载后，旧悬浮控制租约与订阅失效，清除旧任务状态；用户设置不被插件启动覆盖，保留外观须遵循明确策略。
17. 素材采用真实内容哈希与受管资源句柄；同大小不同内容可识别，配置提交原子化，原生配置重置后可查询并受控恢复。
18. 多会话事件有明确跟随/聚合规则，乱序或过期事件不覆盖当前状态；配置成功、资源就绪与实际可见可分别检查。
19. 基座能力发现、未知/未实现能力、权限拒绝、超时后查询、请求去重、事件取消与资源配额有可验证行为；另以通知、文件导出和诊断恢复验证接口通用性。

20. 官方 DSH 账号在目标 Android 真机上完成首次登录，并通过实际受认证操作证明可用；API Key 配置或仅打开登录页面不算通过。此项失败阻断发行。
21. 登录过程中的外部跳转/适用回调或轮询、取消、断网、超时及验证码等交互可完成或明确失败；应用退后台、旋转及进程回收后的恢复不串授权事务，过期/伪造/重复回调被拒绝。
22. 重启、基座覆盖升级和兼容内核更新后登录态可按官方规则恢复；过期、撤销或登录态不可继续使用时可重新认证，换号与退出生效且不误删用户数据。
23. A/R/E 凭据与本地 GUI 连接认证分别验证；切换环境不误用旧 token 或登录回调，修复不覆盖 A 账号，R/E 所需授权可以独立建立。
24. 日志、诊断导出、悬浮事件和工具输出不泄露秘密；权限与接口不能直接读取原始账号凭据。WebView/GeckoView 若均发行，则分别完成全登录链路验证。

25. 代表性社区插件按官方管理流程完成安装、激活、功能验证、升级及卸载；分别报告包安装、Host/Client 激活、权限和功能结果，不要求无关插件依赖 Android SDK。
26. 文件授权失效、网络断连、设备不支持、动作事件取消及无障碍撤销均有明确反馈；自动化拒绝过期节点，手势派发后可重新观察验证。
27. 多模态资源和流支持配额、背压、取消及分类断连处理；GUI 断连不取消 Agent 作业和 PTY 后端，观察订阅可重连，采集流撤权即停止。采集授权不自动授予外发权限，敏感信息不进入无关插件事件或诊断输出。
28. 官方内核升级后执行插件契约回归与能力协商；必需 API 不兼容明确阻断相关功能，不以静默删减官方能力通过验收。

29. 按第 6.5.5 节执行管理事务故障注入：监督器重建、遗留后代、并发入口及更新各阶段中断后不双写，不误杀，不出现代码/profile/数据混搭，也不静默丢失已确认数据。
30. A 工具链安装不修改受管救援运行时；基座升级后断网且 K1 损坏时，完整 K2/E 救援组合仍可用。
31. 可选媒体/能力模块持续异常时，无扩展原生恢复可进入；资源耗尽时执行低水位与保留规则，不删除唯一救援组合或跳过必要快照。
32. 审批与实际目标、通道及环境绑定，目标变化和重启后旧批准失效；基座自动化不能操作本应用审批。安全解包与脱敏注入测试按第 6.5.5 节通过。

33. 每个成功进入 A 的正常启动事件安排一次加密完整备份；R/E 不入包。刷新、旋转、短重连及备份维护续启不重复触发；强杀后对账不重复发布。首次未设密/目录明确待办，自动失败不引发内核切换；手动与自动使用同一流程。
34. 连续完成四次自动/手动备份后，backup 最终只保留最近三份成功包；模拟写失败、取消、目录断权、空间不足与清理失败，不提前删旧包，不删除用户其他文件，不把半包列为可恢复备份。
35. 用户设密后在非应用专属目录生成 backup；卸载重装并重新授权，输入密码可恢复 A profile、插件整目录、闭包实体、启用顺序、patch 和范围内原样设置；范围外登录/依赖明确报告。验证错密码、篡改、截断、换密码及 Keystore 失效；R/E、会话和工作区不被误覆盖。
36. 导入恶意/损坏压缩包、版本不兼容、构建脚本未获批准或验证失败时，当前 A 与原备份保持可恢复；成功解压不等于功能验收通过。基座不新增日常原生操作界面，手动备份、导入导出和状态均经“安卓基座”设置入口提供。

37. 在支持的硬件上完成相机拍照/预览/录像、录音/播放/实时音视频、单次/持续位置、蓝牙发现连接与 BLE 读写/订阅、传感器发现/采样/语义事件的正向闭环。每类均覆盖拒权/撤权、占用、超时、取消和资源释放；不以返回 NOT_SUPPORTED 替代首发实现。
38. 在 MuMu 与 ARM64 手机记录真实 ABI 和系统信息；4GB/64GB 基准下完成启动、空闲、任务、备份、媒体压力测试；按开发指导冻结的预算验收，发布附明确支持矩阵，不宣称所有 Android 版本通过。
39. 补丁 preimage 不符即拒绝构建；文件锁及沙箱能力报告诚实，官方账号/插件契约回归通过，发行声明包含 Android 补丁与依赖许可。
40. 用户密码不出现在日志/普通配置/诊断，SAF 不存在明文包；换机/重装解密不依赖原 Keystore；未认证内容不执行，部分包不替换完整包，启动备份维护重启不形成循环。

先验证最小官方 GUI、真实命令/PTY/锁、一个标准插件、账号登录与四个路线闸门，再落实 A/R/E、事务、加密备份、媒体和设备能力。以上 1–40 是完整首发矩阵，不是一个最小原型的任务量。所有首发必需实现、平台适用项与证据完成后才发行；自动模型诊断和修复在确定性恢复机制之后开发。

## 12. 技术待定项与实现闸门

已确认的产品决策不再列为开放项：ARM64 侧载、targetSdk 28 原型路线、最小兼容补丁、可信插件、停机维护、全部明确能力首发、用户密码加密插件整目录、成功进入后自动备份及手动备份、三份完整包轮换。

### 12.1 必须先完成的四个路线闸门

| 闸门 | 实验 | 通过条件/失败去向 |
| --- | --- | --- |
| 平台兼容 | 锁定官方提交与补丁，真机运行真实文件锁、PTY、子代理和原生绑定 | 不禁用互斥、不改禁止语义；失败先评估最小补丁，否则停路线 |
| 安全表达 | 对沙箱/runner 适配做允许/拒绝及能力状态测试 | 不虚报完整隔离；不能准确表达则适配或阻断，不静默全权 |
| 发行执行 | 检查包名/ELF 前缀、ARM64 载荷、targetSdk 28 在目标设备的安装和二进制执行 | 真实设备通过；现代系统限制不兼容则收窄明确支持矩阵或重新决策执行路线 |
| 管理协调 | 官方安装/HMR/直接命令与快照竞争，维护窗口停写与恢复 | 无并发写入、可确认停止；无法确认时拒绝，不假定官方天然参加监督锁 |

### 12.2 需要实验锁定的技术参数

- 手机型号、Android/API、ABI、WebView 版本；MuMu 版本、镜像 ABI、ARM64 转译能力与资源配置。MuMu 能启动 APK 不证明 ARM64 工具链原生通过。
- 最低/最高支持 Android、关键权限行为版本；开发机硬件虚拟化与 Windows 构建环境。先获取实际信息，不凭模拟器可调版本承诺全系统兼容。
- DSH/DSHAPP/参考分支提交、Node/Termux/原生库/包管理器/JDK/AGP/NDK 等版本及完整许可证。前轮官方提交仅是审查锚点，不自动等于首发版本。
- 系统 WebView 的登录、文件选择、WS、布局与透明媒体验证结果；确有阻塞才评估 GeckoView，不默认双内核 Web 容器。
- 真实 profile/包存储/运行时前缀、依赖闭包和只读快照复制策略；修复允许列表、候选副作用控制与跨环境访问。
- 启动就绪、超时、退避、重试上限、正常进入事件与维护续启的持久实现；进程身份、遗留写者对账、单监督器锁顺序、断电持久化及人工解困。
- 加密库/容器、KDF 与资源参数、Keystore 包裹策略、可移植解密测试、SAF 发布/对账与部分产物配额。不能把密码学实现留到发行前最后一步。
- 更新信任根、密钥轮换、下载源与发布清单；K2/E 固定组合选择及独立更新频率。
- SDK 具体方法/schema、错误映射、权限/流生命周期、悬浮仲裁/隐私、媒体格式与透明视频设备矩阵。它们是待实现契约，不冒充现有官方 Service。
- 性能与空间预算、低水位、应急预留、资源回收、模块故障隔离及压力测试；开发指导给出首轮工程目标，均待测量校准后冻结。

技术参数可依据实验在不削弱已确认范围、安全与数据不丢失边界的前提下调整；更改产品决策或删除首发功能必须重新取得用户同意。

## 14. 总结

一个安卓基座承载日常和应急双内核，一号内核提供日常与独立修复环境，二号提供应急环境。插件和用户配置独立持久化，受管运行时与用户工具链明确分开，Shizuku 与 Root 可选支持。使用全量 APK、基座升级 APK、内核升级包解耦更新；每次升级保留完整救援组合，以单监督器持久事务绑定内核、profile 和数据迁移，通过一致快照及声明范围内的恢复保护用户资产。原生恢复先于可选扩展初始化，审批、日志和资源预算服从可信执行与救援生存边界。

按“路线闸门 → 运行与确定性救援 → 事务及加密备份 → 界面/悬浮/设备能力 → 模型修复 → 发行矩阵”分步实现。全部必需能力完成并验收后发行，不因分阶段开发改变全功能首发承诺。上述方案尚未实施或通过故障注入，文档完整不能替代 Android 原型与真机验证。

核心价值：不人为削弱 Agent 能力，更新不重置用户环境，故障后仍有可靠入口。
